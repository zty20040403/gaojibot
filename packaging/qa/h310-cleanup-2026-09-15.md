## Authorization and Scope

The user explicitly authorized one h310 maintenance connection to inspect and
remove only the previous App installation's unreferenced Nix cache and unused
Docker bridges/rules. This was not deployment authorization. No h610/tank
connection, rebuild, service restart, global GC, Docker prune, or database/user
file deletion was performed. The single SSH session exited with status 0.

## Results

- Historical candidate manifest: 1216 exact store paths recorded by the previous
  cleanup, all still present at inspection. Registration times were checked
  against the original installation window.
- Both `docker0` and `br-2aec133b67ab` had their recorded MAC/IP identities, were
  DOWN, and had no bridge members. No container engine was running and there
  was no independent Docker/containerd installation directory or socket.
- Removed those bridges and the orphan Docker IPv4/IPv6 chains and hooks.
  Compared all remaining rule specifications and chain policies before/after;
  the NixOS and Tailscale rules were unchanged. No firewall reload was used.
- An initial 1125-path selection was rejected by Nix liveness checks before
  deleting anything. Expanded the preservation check to include derivation
  output relationships; did not disable liveness checks.
- Used targeted `nix-store --delete` for 523 paths only. The command succeeded
  and reported **724.6 MiB** freed. All reported deletions belonged to the
  approved selection, and every selected path was absent in the final check.
- Retained 693 candidates with dependencies involving other cached paths.
  Their measured disk usage was **400084992 bytes (381.6 MiB)**. These are
  inactive shared cache, not a running App; cleanup was intentionally not
  broadened to remove the other cached paths.
- Root filesystem available space changed from 194123104256 to 194914451456
  bytes. This is a whole-filesystem observation and includes concurrent normal
  activity; the Nix-reported amount above is the deletion receipt.
