# 软件部署第一版

## 这次能做什么

同一台服务器可以安装多个独立软件实例：高级机器人和静态网站。
已有高级仍使用原来的实例编号、数据库、QQ 登录目录和安装任务，不搬家、不重新初始化。
新增高级实例会使用独立数据目录；请用它自己的 QQ 和模型设置，不要让同一个 QQ 同时登录两处。

## 安装网站

1. 在 App 添加或打开服务器连接。
2. 进入“已部署软件”，点“添加软件”，选择“静态网站”并命名。
3. 选择网页文件夹。根目录必须有非空的 `index.html`；HTML、CSS、JavaScript、图片等静态资源可以一起上传。
4. 核对安装影响，必要时填写服务器 sudo 密码，再确认部署。
5. 显示“运行中 · 页面验证通过”后，点“打开网站”。App 会建立 SSH 加密隧道，不需要手动转发端口。

这一版的新网站部署支持 Ubuntu 22.04/24.04 x86_64，需要 systemd、至少 2 GiB 可用空间，以及 Docker 28 或更新版本。
干净 Ubuntu 上会安装容器环境；已有 Docker 则复用，不自动升级共享 Docker 或删除其他软件。
旧的机器人 NixOS 和本机 Mac/Windows 部署入口保留。静态网站暂不支持这些目标。

## 网站不是源代码构建器

上传的是可以直接打开的网页成品。React/Vue 等项目应先完成构建，再选择输出目录，例如 `dist`。
不要选择带 `.env`、私钥或 `node_modules` 的项目源目录；App 会拒绝这些文件和符号链接。
网站总大小上限 128 MiB、单文件 32 MiB、最多 5000 个文件。
这一版不安装后端 API、PHP、数据库网站，也不自动申请域名或 HTTPS 证书。

## 更新、失败和恢复

- 更新：选新文件夹，确认后启动候选网站。只有真实 HTTP 返回的首页与上传文件校验一致，才替换旧网站。
- 回退：切回上一个保留版本。默认保留当前和前一个版本；不自动删除被其他容器使用或含未知文件的旧目录。
- 关闭 App 或 SSH 断开：服务器任务仍继续。重新连接后查询原任务；不要新建一个同名实例来重试。
- 执行失败：显示失败信息，旧网站不被候选网站覆盖。可修正外部原因后继续原任务；已经安全结束的失败任务也可以提交修正后的内容。
- 服务器重启：服务和持久任务按原实例恢复，不以“连接断了”作为删除或重复安装的依据。

## 访问和删除

网页服务只发布到服务器的 `127.0.0.1`，通过 App 访问，不直接开放到互联网。端口在创建时选择并固定，容器或服务器重启不会重新分配；更新为新容器时可能换端口，App 自动使用新地址。关闭 App 后网页容器仍运行，但本机预览隧道会关闭。
网站容器使用非 root 用户、只读根文件系统和单独的 Docker 网络，默认 0.5 核 CPU、128 MiB 内存；禁用该网络的出站 NAT，不代表它是完整的防外联沙盒。

“停止”保留服务和数据；“卸载”删除该网站容器和专属网络、保留网页和网站备份；保留状态可以重新启动。
“彻底删除数据”需要单独确认实例编号，只删除该实例的网页版本、网站备份和经校验的上传副本，不清理共享镜像、Docker 服务、其他实例或用户原始文件。
“移除此连接”只移除 App 中的连接记录，不卸载服务器上的软件。

## 本版验证边界

使用本机隔离 Ubuntu 虚拟机验证，不自动在 h610、h310、tank 上部署。
QQ 扫码、真实群聊/PDF 收件以及真实 Windows 执行仍需单独验收，不能用界面测试或安装包校验替代。

## 0.1.35：日常查看与整理

- 打开服务器后，软件列表自动读取各实例状态，可以搜索名称，或筛选“进行中”“需关注”。进入详情后暂停列表轮询，避免重复查询；隐藏窗口时也暂停新查询。
- “QQ 已接通”需要数据库就绪、配置已应用、组件运行和近期 QQ 连接心跳同时成立，不代表 API 额度或模型回答已经测试。“网站可访问”需要首页 HTTP 与内容校验通过。
- 无法连接显示状态未知，超过一分钟的旧状态显示已过期，不保留旧的绿色状态冒充正常。鼠标悬停在状态上可看确切检查时间。
- 每行的铅笔只修改本机显示名称，不更改服务器、容器或数据路径。已有高级实例也可以独立改名，不改变服务器名称。
- 垃圾桶只移除从未提交任务的空记录。有安装、更新或维护记录时，后端会拒绝直接移除；服务器卸载仍走实例详情中的服务维护。
- 安装页显示任务历时、服务器进度更新时间；展开“任务详情”可看原始任务编号和创建时间。断连时显示断连前记录，不假装进度继续推进；没有服务器时间时明确显示等待回执。

本次只修改桌面层，使用本地模拟 IPC 和真实 Electron 窗口验证，不重复运行重型服务器部署测试，也没有连接生产服务器。

## 0.1.36：网站备份与迁移

1. 在网站详情点“创建备份”，保存当前网页的独立副本，不停止网站。
2. 每份备份显示确切时间、文件数和大小。恢复箭头将先验证候选页面再替换网站，失败时当前网站保留。
3. 下载按钮导出 `.gaojibak`，使用独立的至少 12 字符密码加密。妥善保存密码，App 不保存它，也无法帮你找回。
4. 换服务器时，先建立新的“静态网站”实例，再点“导入备份”，输入备份密码并选择文件。校验通过后仍需点击“部署网站”并确认，导入本身不会改服务器。
5. 垃圾桶只删除选中的服务器备份，不删除当前网站或已导出到电脑的文件。卸载保留备份；彻底删除实例会一起删除其服务器备份。

备份仅包含网页成品，不包含服务器账号、域名、证书或其他软件。最多每站 20 份，达到上限时请先导出或删除；不会偷偷轮换删除旧备份。创建备份不依赖 Docker 正常运行，恢复仍需要可用的容器环境。备份采用手动触发，本版没有定时备份。

导入经完整密码认证后会在电脑的 App 私有缓存中暂存网页包，以便断线后继续原任务；服务器确认完成后清理。导入限额与普通网站一致，不接受机器人备份或任意可执行安装包。
