# 限时静态预览

## 使用方式

在已启用沙箱、Sub-Agent 和 Fleet 的群里，直接描述需要的小网页或小游戏：

> 帮我做个班级活动倒计时网页，手机和电脑都能看，检查完发一个有效一小时的预览链接。

模型负责生成代码、构建和检查；后台工作流负责等待发布回执。最终消息包含实际地址、
任务修订版本和到期时间。模型漏写链接时，宿主仍会从当前任务的持久回执补上。
例行任务内的子任务不另发一条消息，已发布的链接由例行任务最终 Outbox 一并交付。

前置条件：

- 配置 `AI_CLUSTER_ENABLED`、`AI_CLUSTER_CONTROL_URL` 和独立凭据文件；群进入
  `AI_FLEET_ALLOWED_GROUPS`，调用者通过沙箱访问策略。
- 启用 `AI_SUBAGENTS_ENABLED` 和 `AI_SUBAGENT_ENTRY_ENABLED`。重启后自动补发的
  交付保证针对持久后台工作流，不适用于只在前台手动提交一个 Fleet 作业便结束的调用。
- Control 已登记至少一个支持 `preview.static` 的 Worker，其 `public_base_url`
  必须是收件人能访问的地址。Worker 所有者或有效借用授权仍须满足现有资源策略。
- Worker 的预览服务应与控制台、认证服务分开监听。这里不会自动打开公网防火墙，
  也不会自动创建反向代理或绕过借用额度。

## 发布与恢复

1. 在隔离沙箱里生成并构建网页。ZIP 根目录放 `index.html`；只有一个顶层项目目录时，
   也允许该目录下的 `index.html`。多个候选根目录不会猜测选择。
2. `cluster_artifact_upload` 上传当前用户、当前会话拥有的产物，获得 `artifact_id`。
3. `cluster_job_submit(kind="preview.static")` 提交发布；默认一小时，允许五分钟至七天。
4. `queued`、`running` 仅代表处理中。后台记录提交意图，重启后查询同一个远程句柄；
   提交回执丢失时复用同一个幂等键，不重新生成不同的有效期和链接编号。
5. Worker 原子展开并登记预览。重复发布核对文件 SHA-256、URL 和到期时间，
   不会把不同文件悄悄覆盖在同一地址。失联接管重新确认本地文件，不能把另一台机器
   的旧 URL 当成本机已经发布。
6. 成功回执的地址必须精确匹配实际 Worker 与本次预览编号。宿主把回执加入最终消息，
   通过现有 Outbox 发送到原会话和原账号。发送回执不明确时沿用现有核对机制，不盲目重发。

原请求重试不会延长 TTL。过期后需新提交，不应拿旧幂等键续期。
显式 `deadline_at` 仍受请求校验限制；过期后应按作业句柄查询，而非重新提交过期请求。
发布结果是文件发布回执，不代表远程收件人的网络实测成功，也不替代功能、视觉或附件验收。

## 隔离与容量

- ZIP 上传上限 25 MiB、解压上限 100 MiB、最多 5,000 个条目。
- 拒绝隐藏文件、目录穿越、符号链接、特殊文件、重复路径和控制字符。
  这不能自动找出所有写进普通文件的秘密，打包前仍须排除凭据和私密资料。
- 预览支持 HTML/CSS/JS 与本地静态素材，不运行后端进程。CSP 使用不透明沙箱源，
  不允许读取 Cookie/本地存储、提交表单或发起 API 请求；外部脚本、CDN 依赖应在构建时打包。
  匿名 CORS 只用于静态资源，支持 ES module 导入，不开放控制接口。
- 知道随机地址且网络可达的人可读取页面。发布、查询接口有用户和会话隔离，
  **预览页面不是群成员认证入口**。不要把内网地址当作私密访问控制。
- 到期立即拒绝页面读取；Worker 正常控制循环随后清理展开目录。
  解压临时目录有最多一小时的期限，进程异常退出后也能清理。Worker 停机或控制循环
  无法继续时，磁盘清理需等待恢复；路由到期检查不依赖后台清理是否执行。
- 上传到 Control 的源 ZIP 不由预览 TTL 连带删除；当前没有按预览期限自动回收这些
  源 ZIP。管理员仍需规划产物存储容量，不能把“预览已清理”理解为所有副本已删除。

## 验收边界

本地测试覆盖真实 PostgreSQL 并发提交、事务失败、旧孤儿记录、租约接管、范围隔离、
ZIP 安全、链接过期、持久最终投递，以及 Playwright 桌面/手机上的模块脚本与小游戏交互。

这些不证明线上已启用。获准部署后仍需在测试群验收：实际模型生成、Worker 网络可达、
QQ 离线重连后的链接投递和真正到期后的 404。部署时应一起升级 Bot、Control、Worker；
不要只启用新的可重试策略却保留旧 Worker 的发布实现。
已入库旧作业保留旧的安全策略，不会因升级自动获准重新执行。

项目持久版本、独立工作台认证和项目预览源属于后续项目空间计划，此处没有冒充已完成。
