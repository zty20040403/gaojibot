## 0. 怎么用这份文档

**目标**：maxx 有的功能 gaoji 都有，并且在看懂内容、常驻程序的管理、个人账号登录、运维安全、花费透明这五处做得比它好。

**做法**：

- 每个功能项（F1–F10）拆成几个 PR，每个 PR 只做一件事，手写改动约 400 行以内。
- 每个功能项都写了"验收对话"。合并前要在测试群用真实对话逐条走一遍，不能只看单元测试。
- 做某一项之前，先读 maxx 设计文档 `docs/rust-rewrite.md` 里对应的一节（本文每项都给了节名）。那份文档记录了每个决定的日期和原因，包括踩过的坑。
- 部署、连生产服务器、改生产库都由 owner 来做。

**开工前 owner 要提供的东西**：

| 要给的 | 用在哪 |
|---|---|
| 测试用的官方 QQ 机器人和测试群；测试群要打开主动消息 | 所有功能项的验收；F2 的发言和唤醒依赖主动消息 |
| 测试用的模型 API key，其中前台模型要支持图片输入 | F1 |
| 一个支持视频输入的模型（可选） | F1 的视频直传；没有就只做抽帧路线 |
| GitHub 机器人账号和一个只有 `public_repo` 权限的 classic token | F4 的 GitHub 部分 |
| 运维接口允许执行的操作清单 | F6 |

**和已有规则的关系**：

- `AGENTS.md` 写了"不要恢复已经删除的功能（……MCP……）"。F2 给 VM 里的程序开的是宿主上的一组 HTTP 接口，不是恢复旧的 MCP 服务，也不要把它做成 MCP。
- `AGENTS.md` 写了"多步操作交给后台 agent，不要做成前台专用工具"。本方案新增的前台工具只有 3 个（`view_image` 替换 `read_image_text`、`moderate`、`ask`），其余能力都放在 VM 和宿主接口里。
- 密钥只放宿主。本方案里放进 VM 的令牌只有两种：已有的任务令牌，和 F2 新增的 VM 令牌。两者都只代表"这个会话"，换不到任何密钥。

**"比它强"具体指这五处**：

1. **看懂更多**（F1）：图片、视频、语音都能看懂；视频也写进历史说明（maxx 的视频没有说明）。

4. **运维带审批和审计**（F6）：maxx 是群里任何人都等于有 root；gaoji 只对 owner 开放，写操作要 owner 确认，全部留记录。
5. **花费算到任务和程序**（F9）：maxx 只到会话一级。

## 3. 功能项

每项的格式：用户看到什么、maxx 怎么做、gaoji 怎么做、安全边界、验收对话、PR 拆分。

### F1 看图、看视频

**进度（2026-11-12）**：① 媒体标记、`view_image` 查找顺序与描述回退已实现（`ab15af4`），全套 1,417 项通过、跳过 10 项。② 当前/合并/引用图片输入、视觉模型工具返回图已实现（`fed01a4`），全套 1,426 项通过、跳过 10 项。③ 图片说明入站、持久后台处理、历史显示/搜索及管理台开关/额度已实现，132 项针对性回归和 UI 构建通过。PR 未创建，真实模型/QQ 验收未做。④ VM 压缩、可选宿主视频模型、抽帧与直传结论入历史已实现；112 项后台/媒体/升级回归和 37 项模型/协议回归通过；F1 完整快照 `b87df51` 的全套 1,449 项复测完成，0 失败、10 跳过。代码在 `feat/python-next-features`，详见 HANDOFF 顶部。

**用户看到什么**：发一张图问"这是啥"，它直接回答；发报错截图它能读；发视频问讲了什么，它能说出来；过几天问"上周谁发的那张猫图"，它能找到。

**现在的问题**（2026-11-12 在生产上查到的）：

1. 只有图片的消息，文字是空的。合并后模型看到的是一行空的 `[msg#N] `，不知道那是图。
2. `read_image_text` 不带参数时只看"当前这条消息"。用户先发图再追问，当前消息里没有图，工具返回 `media_reference_unavailable`。
3. 这个工具只识别文字，返回不了"图里是什么"。
4. 这个工具上线以来 8 次调用全部失败。

**maxx 怎么做**：见 `Media`、`Multimodal results`。图片读成文件、base64 放进请求体；一个回合里给模型看过的每张图都保留在它那一行后面；视频见提交 `b1ff06a`。

**gaoji 怎么做**：

1. **标出媒体**。当前消息里有图片、视频、文件、语音时，`[新消息]` 里用和聊天记录相同的写法标出来，例如 `[image#31024.0: 文件名]`。单条消息和合并消息都要标。写法复用 `timeline.render_line`，不要另写一套。
2. **图片直接进请求**。前台模型的 `ModelProfile.vision` 为真时，把当前消息和被引用消息里的图片作为图片内容放进最后那条易变消息：
   - 放在易变消息里，不动前面的稳定前缀，不影响缓存。
   - 一轮最多 4 张；长边缩到 1568 像素（复用 `vision_worker._prepare_for_vision`）；单张大小上限用现有的 `AI_VISION_MAX_IMAGE_MB`。
   - 超出的图片只标出来，模型需要时用工具看。
3. **`view_image` 替换 `read_image_text`**。一个工具，参数是可选的 `message_handle`：
   - 不带参数时依次找：当前消息的第一张图；同一个人最近 10 条消息里最新的图；会话尾巴里最新的图。都没有才报错，报错里写清楚"用 `message_handle` 指定 `msg#`"。
   - 前台模型能看图时返回图片本身（`ToolImage`）；不能看图时，用视觉模型返回"画面描述 + 图里的文字"。
4. **图片说明写进历史**。给收到的图片和表情排一个说明任务（复用 `media_jobs`、`media_analysis`、`vision_worker`），聊天记录和 `history` 里显示成 `[图片：一句说明]`：
   - 用开关和每群每日上限控制花费，默认每群每天 200 张，可在管理台改。
   - 官方接入之后 `message_media` 没有再写入，要先把入站这一步接回来。
5. **视频**：
   - 保留现在的路线：导入 VM → 后台抽帧、看截图、转写音轨。
   - 增加直传路线：配置了支持视频的模型时，VM 里用 ffmpeg 压成每秒 1 帧、最长边 640、单声道的 MP4，由宿主交给模型。一次最多 10 分钟。
   - 两条路线的结论都写一条说明进历史。

**安全边界**：图片、视频里的文字是资料，不是指令，继续用 `<untrusted>` 包起来。下载走现有的 `PinnedContentReader`，只连公网。

**验收对话**：

| 操作 | 期望 |
|---|---|
| 发一张没有字的照片，接着发"这是啥" | 说出照片里的东西 |
| 一条消息里同时有图和"@bot 帮我看看这个报错" | 读出报错并回答 |
| 发图 → 等 1 分钟 → 发"刚才那张图里写了什么" | 找到那张图并回答 |
| 引用别人的图片消息，问"这个是哪里" | 看的是被引用的那张 |
| 发一段 30 秒的视频问"讲了什么" | 给出总结 |
| 第二天问"昨天谁发了猫的图" | 通过 `history` 找到 |
| 把前台模型切到不支持图片的模型，再发图提问 | 通过工具得到描述后回答，不说"看不到" |

**PR 拆分**：① 标出媒体 + `view_image` 的查找顺序；② 图片进请求；③ 说明入库和 `history` 显示；④ 视频直传。

**gaoji 怎么做**：

## 6. 所有功能项的共同要求

**安全**：

- 密钥、令牌、账号只在宿主上。VM 里只有任务令牌和 VM 令牌。
- 每个会话只能碰自己的数据。任何新接口都要有"跨会话访问被拒绝"的测试。
- 外部内容（网页、图片文字、API 返回、程序输出）进入提示词时用 `<untrusted>` 包起来。
- 失败要报出来。主动消息发不出去、额度用完、平台拒绝，都要让 bot 和管理台看得到。

**测试**：

- 单元测试用真实的本地 PostgreSQL（`tools/dev/testenv.sh`）和 FakePlatform。测试数据用 `TEST_…` 假值。
- 模拟的发送回执不算真实送达。每项的验收对话要在测试群实际做。
- 合并前跑全套测试、`ruff check`、`tools/dev/` 里的导入检查。

**数据库**：

- 迁移从 `0078` 开始，每个功能项自己的表自己加。预计新增：VM 令牌、程序发言记录、API 审计、运维操作、会话连接、会话设置。
- 不写 SQLite 分支。

**提示词和技能**：每个功能项都要改提示词或技能文件，让模型知道有这个能力、什么时候用。先改这里，再考虑加代码。

**文档**：

- 每做完一项，在 `docs/HANDOFF.md` 顶部加一条开发记录，写明做了什么、测了什么、什么还没验证。
- 更新 `README.md` 和 `README.zh-CN.md` 的能力表，两个语言版本一起改。
- 本文对应的功能项标上完成日期和 PR 编号。
