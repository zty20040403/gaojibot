# ADR 002：原文是事实，摘要与向量是可重建的索引

状态：采用。作者：Kenneth。日期：2026-09-07。

## 问题

群友经常先说一件事，再单独问“你觉得呢”。只抓上一条提问、固定条数窗口或只拿最高分
向量，会错过普通群聊中的当前话题。不断压缩旧摘要还会让错误逐步变成“记忆”。

## 决策

- 以连续、按时间排列的原文理解当前对话，根据模型 token 预算决定覆盖范围，不以曾经
  是否 @ 机器人作为话题权重的唯一依据。
- 原始消息与摘要分开保存。章节记录来源消息编号、范围和哈希，能回到原文验证。
- Historian 是后台投影任务；发布章节和推进覆盖游标必须在同一事务完成。
- 章节的 P1/P2/P3 提供不同信息密度；P4 是低价值内容的检索档位，不代表删除原文。
- 语义召回使用 BGE-M3 和可选 pgvector 索引辅助寻找旧话题，不用向量代替原始证据。
- 群记忆、个人记忆和群时间线分别保存归属。工具查询时再次检查范围。

明确引用可优先定位对象；没有引用时仍应读取相邻的群聊。证据不足不能编造，但也不应
仅因某条消息分数稍低，就强迫群友重新引用已经在上下文中的内容。

## 实现位置

`src/plugins/ai_chat/` 下的 `ledger.py` 保存事实，`context_store.py` 管理章节及游标，
`historian.py` 执行后台整理，`semantic_recall.py` 维护语义投影，
`long_term_memory.py` 保存带版本和来源的长期记忆，`turn_journal.py` 保存本轮证据轨迹。
`tools/context_eval.py` 与上下文评测 fixtures 用于回归比较。

## 取舍

不采用固定“最近 N 条”作为唯一上下文：消息长度和话题密度不同。
不只依赖模型主动搜索历史：短追问也需要自动获得当前对话。
不把历史摘要作为不可修改事实：节省空间不是牺牲可验证性的理由。
代价是保留原文的存储成本，以及摘要、向量等派生数据的后台维护开销。

## 回归检查

覆盖没有 @ 的前文、多用户交错发言、隔天接续和突然换话题；检查是否用了正确原始消息，
而不只检查最终回答措辞。相同文本出现在不同群时不能串群，不能把另一人的经历当成本人。
关闭 Historian 或 embedding 后应仍能用原文时间线聊天。

## 2026-10-26：稳定前缀与资料边界

- System 只放稳定的人设、工具规则和已验证的主机名。群时间线是第一条 user 资料消息；
  分钟时钟、当前用户、记忆、搜索、OCR 与本轮提示放到最后的问题旁边。
- 原文窗口仍按 token 预算取连续后缀，起点按 8 条分块移动，保留最小现场数量。
  这不是只保留最近 8 条，也不改变群和用户的查询权限。
- `prompt_context.py` 为外部资料添加 `untrusted` 边界，并转义其中的标签。
  动态资料使用随机边界；不变的历史块使用进程随机密钥生成的稳定 HMAC 边界，
  否则每轮随机数会使缓存前缀失效。重启后密钥变化，不持久保存第二份聊天缓存。
- 这是提示词层的防御，不是防注入的数学保证。Scope、工具权限、批准和沙盒隔离仍必须
  由代码检查。工具资料和含外部文本的校验错误不能作为 System 指令注入。
- 工具回执在模型请求边界转义，原始审计记录不被改写。分页证据同时计入转义和边界的
  长度，不能把传输时被截断的页面记作完整已读。
- Anthropic 为 System 和群资料设置显式缓存断点；OpenAI-compatible 请求不添加
  非标准缓存参数。缓存是否生效仍取决于提供商、前缀长度、模型和有效期。

控制台的模型调用趋势可切换到“缓存命中率”，悬停显示输入、输出、缓存 token 的确切
数量。命中率是累计缓存输入除以累计输入，不是每日百分比的简单平均。Anthropic 的
输入总量包括普通输入、缓存读取和缓存创建，只有缓存读取计入命中。
`gaoji_model_cached_tokens_total{profile}` 是输入 token 的子集，不能再与输入相加。
缓存规则依据 [Anthropic 官方说明](https://platform.claude.com/docs/en/build-with-claude/prompt-caching)。

本地回归验证前缀稳定、伪造闭合标签、分页预算和缓存计数；部署后仍需观察一天的
真实缓存输入占比，不能用本地截图中的模拟数值声称节省了实际费用。
