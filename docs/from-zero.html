阅读方式

先做小，再做全

不要一上来就写现在这套六千多行的完整机器人。正确顺序是：先让消息通，再让模型回答， 最后才增加记忆、搜索、语音和沙盒。

里程碑 A

程序能启动

里程碑 B

QQ群能问答

群里 @机器人，消息交给 DeepSeek，再返回文字。

里程碑 C

对话有连续性

按群和用户隔离上下文，记住昵称并引用回复。

里程碑 D

每个阶段都要先验证 前一步跑不通时不要继续堆功能。否则报错时，你不知道问题来自 QQ、NoneBot、DeepSeek，还是新加的工具。

基础概念

先认识这几个角色

QQ 客户端真正登录机器人 QQ 号的程序。
NapCatQQ把 QQ 消息转换成程序容易处理的数据。
OneBot V11规定“群消息、图片、@、回复”应该长什么样。
NoneBot2收到事件后，决定交给哪个 Python 方法处理。
Uvicorn监听端口并维护 WebSocket 连接的网络服务器。
DeepSeek API接收文字消息，返回模型生成的回答或工具调用。

一次普通问答实际发生了这些事情：

1. 群友发送消息例如：@机器人 递归是什么？
2. NapCat 产生 OneBot 事件里面包含群号、QQ号、消息 ID 和消息段。
3. NoneBot 匹配处理器发现机器人被 @，运行 handle_mention_ai()。
4. 插件组装上下文加入人设、近期聊天、当前用户和长期记忆。
5. DeepSeek 返回结果它可能直接回答，也可能先要求调用一个工具。
6. NoneBot 发送回复NapCat 把 OneBot 回复消息变成真实 QQ 消息。

逐行看懂虚拟环境命令
代码片段详细解释
python3 -m venv .venv-m 表示让 Python 运行一个已安装模块；这里运行标准库 venv，并把独立环境创建在当前目录的隐藏文件夹 .venv 中。

包名>=最低版本,<下一个不兼容版本 表示：允许安装这个范围内满足条件的版本。例如 openai>=1.0.0,<2.0.0 可以升级 1.x，但暂时不自动进入可能破坏接口的 2.x。

nonebot2[fastapi] 中的方括号表示安装 NoneBot 时额外安装 FastAPI 驱动所需依赖，不是列表语法。

拆开解释 pip install -r requirements.txt
部分详细解释
pip当前 Python 环境的第三方包管理器。激活 .venv 后，它会把包安装到项目虚拟环境。
install要求 pip 下载并安装依赖；已经安装且满足版本条件的包通常不会重复下载。
-rrequirements file 的缩写，表示后一个参数是依赖清单，不是一个包名。
requirements.txt当前目录中的文本文件。pip 逐行读取包名和版本条件，并自动解决这些包的间接依赖。

更稳妥的写法是 python -m pip install -r requirements.txt，它明确要求“当前这个 Python”运行 pip，减少 Python 与 pip 指向不同环境的情况。安装依赖不会启动机器人。

这些依赖分别负责：

  • nonebot-adapter-onebot：识别 OneBot V11 消息。
  • openai：DeepSeek 使用兼容 OpenAI 的 API 格式。
  • python-dotenv：读取 .env。
  • httpx：后续联网搜索和下载图片。
检查点：运行 python -c "import nonebot, openai; print('OK')"，应该输出 OK。

逐行看懂 .env：每一项到底控制什么
配置值的含义对机器人的实际影响
DRIVER=~fastapiDRIVER 是 NoneBot 的驱动配置；~fastapi 是 NoneBot 表示 FastAPI 驱动的简写。让 NoneBot 能启动一个 Web 服务，接收 NapCat 发来的 WebSocket 连接。
HOST=127.0.0.1127.0.0.1 是本机回环地址，只代表运行机器人的这台电脑。默认只有本机程序能连接 8080 端口，适合 NapCat 与机器人运行在同一台电脑的情况。
PORT=8080Web 服务监听的端口号，可以理解成这项服务在电脑上的“门牌号”。NapCat 的反向 WebSocket 地址也必须写 8080；若端口被占用，可两边一起换成别的端口。
LOG_LEVEL=INFO日志详细程度。常见级别有 DEBUG、INFO、WARNING 和 ERROR。INFO 会显示启动、连接和普通运行信息，适合平时使用；排错时可临时改成 DEBUG。
COMMAND_START=["/"]命令开头列表。这里使用类似 JSON 的列表写法，列表中只有一个斜杠。on_command("ai") 因而由 /ai 触发，而不是普通聊天中出现“ai”就触发。
NICKNAME=["gaoji"]机器人可以被识别的称呼列表，不是 QQ 群名片的强制修改项。某些 to_me 规则可以把这些称呼当成“正在叫机器人”；真实 @仍由 OneBot 的 at 消息段识别。
DEEPSEEK_API_KEY=...DeepSeek 发给你的秘密凭证，相当于 API 账户的密码。每次调用模型都要带上它。缺失时请求无法认证；泄漏后别人可能消耗你的额度。
DEEPSEEK_BASE_URL=...DeepSeek API 的根地址。客户端会在这个地址后访问聊天接口。使用兼容 OpenAI 协议的其他服务时，通常就是修改这里和模型名。
DEEPSEEK_MODEL=deepseek-chat本次请求使用的模型标识，不是展示给群友看的机器人昵称。deepseek.py 会把它原样放入请求的 model 参数。
AI_SYSTEM_PROMPT=...系统提示词，描述身份、说话风格、边界和行为规则。它会作为 system 消息随请求发给模型。它不是聊天记录，也不会自动让模型永久记住群友。

.env 的基本格式是 名字=值。这里不要在名字前后乱加空格，也不要给真实 Key 添加 Markdown 代码符号。程序启动时读取一次配置，所以修改后通常要重启机器人。

再创建 .gitignore：

.venv/
.cache/
.env
__pycache__/
*.pyc
逐行看懂 .gitignore：为什么这些文件不上传
规则含义
.venv/忽略整个虚拟环境目录。它体积大、与当前系统有关，而且可以由 requirements.txt 重新安装。
.cache/忽略运行时缓存。缓存丢失后可以自动生成，没有必要进入 Git 历史。
.env忽略保存 API Key 和本机配置的文件，这是最重要的一条隐私规则。
__pycache__/忽略 Python 自动生成的字节码缓存目录。
*.pyc* 是通配符，表示忽略所有以 .pyc 结尾的编译缓存文件。

末尾的 / 表示目录。还要注意：.gitignore 只会阻止尚未被 Git 跟踪的文件；如果密钥已经提交过，仅仅新增忽略规则不会把它从历史中删除，必须立刻撤销旧 Key。

API Key 只能放在 .env 不要写进 Python、README、截图或群聊，也不要上传 GitHub。提交前运行 git status，确认列表中没有 .env。

HOST=127.0.0.1 表示只允许本机连接。如果 NapCat 和机器人位于不同机器，之后需要改为合适的监听地址，并配置防火墙和访问控制。

第 5 步

编写 config.py

配置层只做一件事：把环境变量转换成 Python 对象。先写一个最小版本：

import os
from dataclasses import dataclass


@dataclass(frozen=True)
class Settings:
    deepseek_api_key: str
    deepseek_base_url: str
    deepseek_model: str
    system_prompt: str

    @classmethod
    def from_env(cls) -> "Settings":
        return cls(
            deepseek_api_key=os.getenv("DEEPSEEK_API_KEY", "").strip(),
            deepseek_base_url=os.getenv(
                "DEEPSEEK_BASE_URL", "https://api.deepseek.com"
            ).strip(),
            deepseek_model=os.getenv("DEEPSEEK_MODEL", "deepseek-chat").strip(),
            system_prompt=os.getenv(
                "AI_SYSTEM_PROMPT", "你是一个友好的QQ群助手。"
            ).strip(),
        )


settings = Settings.from_env()
逐行看懂 config.py：把文字配置变成 Python 对象
代码Python 语法在项目里的作用
import os导入 Python 标准库模块，不需要额外安装。使用 os.getenv() 读取由 load_dotenv() 放入环境中的值。
from dataclasses import dataclass从标准库导入类装饰器。让一个主要用来保存数据的类少写很多重复代码。
@dataclass(frozen=True)@ 是装饰器语法；它在类创建时加工下面的 Settings。frozen=True 表示实例创建后字段不能重新赋值。自动生成构造方法，例如可以写 Settings(deepseek_api_key="...")，并防止运行中误改配置。
class Settings:定义一个名为 Settings 的类，冒号后缩进的内容都属于这个类。把散落的模型配置集中为一个有名字、有字段的对象。
deepseek_api_key: str: str 是类型标注，表示期望这个字段是字符串；其余三行同理。编辑器能提示拼写和类型。标注本身通常不会在运行时自动阻止错误值。
@classmethod把下面的方法变成类方法，调用时第一个参数接收类本身。允许写 Settings.from_env()，不需要先凭空创建一个 Settings 实例。
def from_env(cls) -> "Settings":cls 代表当前类；-> 是返回值类型标注；引号中的 "Settings" 是向前引用。承诺这个方法会根据环境变量返回一个新的配置对象。
return cls(...)return 把结果交还给调用者；cls(...) 调用 dataclass 自动生成的构造方法。把下面四个读取结果一次装进 Settings。
os.getenv("DEEPSEEK_API_KEY", "")第一个参数是环境变量名；第二个参数是找不到时使用的默认值。Key 没配置时先得到空字符串，真正调用模型前再给出明确错误。
.strip()字符串方法，删除开头和结尾的空格、换行和制表符。避免复制配置时多出的空白让 Key、URL 或模型名失效。
os.getenv(
  "DEEPSEEK_BASE_URL", ...
)		一对圆括号里的表达式可以自然换行；逗号分隔参数。这一段看起来有三行，实际仍是一次 getenv 调用，只是为了不让单行太长。
settings = Settings.from_env()在模块最外层调用类方法，并把结果存入全局变量。第一次导入 config.py 时立即读取配置。其他模块可直接 from .config import settings；修改 .env 后需要重启。

这个文件只负责“读取和整理配置”，不会连接 DeepSeek，也不会监听 QQ。把职责分开以后，配置读取出错时更容易定位。

当前完整项目还在这里加入了搜索、OCR、语音、记忆、暖场和沙盒的配置，但原理没有变化。配置变多时再加入 _get_int()、_get_bool() 等安全解析方法。

接入 DeepSeek

接下来编写 deepseek.py。最小版本只需要创建客户端并发送聊天请求：

from openai import AsyncOpenAI

from .config import settings


_client: AsyncOpenAI | None = None


def _get_client() -> AsyncOpenAI:
    global _client
    if not settings.deepseek_api_key:
        raise RuntimeError("还没有配置 DEEPSEEK_API_KEY")

    if _client is None:
        _client = AsyncOpenAI(
            api_key=settings.deepseek_api_key,
            base_url=settings.deepseek_base_url,
            timeout=60.0,
        )
    return _client


async def ask_deepseek(user_text: str) -> str:
    response = await _get_client().chat.completions.create(
        model=settings.deepseek_model,
        messages=[
            {"role": "system", "content": settings.system_prompt},
            {"role": "user", "content": user_text},
        ],
    )
    return (response.choices[0].message.content or "").strip()

举例：传入 user_text="你好" 后，请求中会有一条系统消息和一条“你好”的用户消息；DeepSeek 返回响应对象，最后一行把第一条候选回答抽出来。这个最小版本暂时没有重试、错误翻译、上下文和 Tool Call，后面再逐层加入。

为什么使用 async 和 await？

网络请求可能要等几秒。await 表示等待 DeepSeek 时把运行机会交给其他任务，机器人不会因为一个人的问题完全卡住。

messages 是什么？

  • system：机器人的身份、规则和回答风格。
  • user：用户这次提出的问题。
  • assistant：模型以前回答过的内容，后面做上下文时会加入。
  • tool：工具执行结果，后面做 Tool Call 时会加入。

第二部分：注册 /ai 与 @机器人两个触发器
代码参数含义触发效果
ai = on_command(...)函数返回一个 Matcher，并把它保存到变量 ai。这个变量不是 AI 回答文本。以后用 @ai.handle() 给这个接收器登记处理函数，也用 ai.finish() 结束处理。

priority=10Matcher 的处理优先级；NoneBot 中数字越小越早检查。/ai 会早于下面优先级 20 的普通 @消息处理器，避免同一条消息被重复回答。
block=True当前 Matcher 成功完成后，阻止更低优先级 Matcher 继续传播这条事件。一条 /ai 消息只产生一份回答。
mention_ai = on_message(...)创建所有消息类型的 Matcher，再由 rule 缩小范围。负责没有使用 /ai、但明确叫了机器人的消息。
rule=to_me()这里的括号先创建一条规则，再把规则交给 on_message。普通群聊不会每句都触发；@机器人或其他被识别为“对机器人说”的消息才会触发。
priority=20比 10 晚处理。先把明确命令交给 ai，剩余的 @消息才由 mention_ai 接手。
第三部分：reply_to() 怎样拼出一条引用回复
代码语法解释得到的结果
def reply_to(...):def 定义普通函数。它只在内存里组装消息，不需要网络等待，所以不用 async。输入原事件和回答文本，输出可发送的 OneBot Message。
event: MessageEvent参数名后面的类型标注说明期待消息事件。让函数可以读取原消息的 message_id。
text: str表示回答正文应是字符串。这个字符串稍后变成 QQ 文本消息段。
-> Message返回值类型标注，不是发送操作。告诉读代码的人和编辑器：这个函数返回完整消息对象。
return Message([ ... ])列表中的每一项都是一个消息段，排列顺序就是发送时的顺序。构造“先引用原消息，再显示回答文字”的一条消息。
MessageSegment.reply(event.message_id)读取事件的原消息 ID，并以它构造 reply 段。QQ 客户端显示被机器人引用的那条消息。
MessageSegment.text(text)把普通 Python 字符串包装为 text 段。在引用后显示 DeepSeek 的回答。

类型标注主要帮助阅读和检查，通常不会自动在运行时强制类型。这个最小函数只有引用和文字，还没有加入 MessageSegment.at(event.user_id)，所以它会引用原消息，但不额外 @提问者。

第四部分：两个 async 处理函数逐行执行什么
代码语法解释运行时发生什么
@ai.handle()@ 是装饰器。模块被导入时，它把紧接着的函数登记到 ai Matcher。现在只是“登记”；真正收到 /ai 时，NoneBot 才调用下面的函数。
async def handle_ai(...)定义异步处理函数，可以在内部使用 await。网络请求期间不会把整个机器人堵住，事件循环还能安排其他协程运行。
event: MessageEventNoneBot 根据类型和参数名把当前事件注入进来，不需要自己调用 handle_ai。包含原消息 ID、消息正文、用户和群信息。
args: Message = CommandArg()这里看似默认值，实际是 NoneBot 的依赖注入声明。NoneBot 自动把命令后的内容放进 args；命令名 /ai 本身不在里面。
-> None标注函数不把普通结果 return 给调用者。处理器通过 finish() 直接发送 QQ 消息并结束。
args.extract_plain_text()从 Message 的多个消息段中提取纯文本。图片、@等非文字段不会被直接拼进问题；得到用户写在命令后的文字。
.strip()删除开头和结尾空白。/ai    最终会得到空字符串，而不是三个空格。
if not question:空字符串为假，not 后条件成立。用户没写问题时进入用法提示分支。
await ai.finish(...)发送消息后，NoneBot 的 finish 会通过内部结束异常终止当前 Matcher 流程。发出“用法”后不会继续向下请求 DeepSeek，因此这里不必再写显式 return。
answer = await ask_deepseek(question)等待异步模型函数完成，再把返回字符串赋给 answer。当前处理器暂停等待网络；拿到回答后继续下一行。
await ai.finish(reply_to(event, answer))先调用 reply_to 组装 Message，再等待 Matcher 发送并结束。群里收到引用当前问题的 DeepSeek 文字回答。
@mention_ai.handle()把另一个函数登记给 @消息 Matcher。这个函数只在 to_me() 规则成立时执行。
event.message.extract_plain_text()这里没有 CommandArg()，直接从完整事件消息取文本。@机器人 递归是什么 中的文字成为问题；适配器负责识别 @消息段。
mention_ai.finish(...)必须使用当前 Matcher 的 finish。空问题时提示“你想问什么？”，正常时发送模型答案，然后结束处理。

命令路径：/ai 递归是什么 → ai Matcher → args 得到“递归是什么” → DeepSeek → 引用回答。

@路径：@机器人 递归是什么 → to_me() 成立 → mention_ai Matcher → 从 event.message 取文字 → DeepSeek → 引用回答。

这是为了第一次跑通而写的最小版本 它还没有 API 异常处理、输入长度限制、上下文记忆、群白名单、额外 @提问者和 Tool Call。先确认一问一答通了，再加这些能力，出错时才知道是哪一层的问题。
检查点：到这里，Python 代码已经能完成最小问答。还差最后一段：让真实 QQ 消息进入 NoneBot。

第 10 步

让机器人记住前文

最小机器人每次只发送当前问题，所以用户问“那第二个呢”时，模型不知道“第二个”指什么。于是增加 memory.py。

核心思想是给每个会话保存最近几轮：

group:123456789:user:987654321
├── user: Python 的列表是什么？
├── assistant: 列表是一种有顺序的容器……
├── user: 那元组呢？
└── assistant: 元组和列表类似，但通常不可修改……
这棵“会话树”每一行表示什么
内容含义
group:...:user:...这份记录的唯一会话键，表示某个群中的某个用户。数字只是教学示例。
user: Python 的列表是什么？第一轮用户消息；保存时不仅要存文字，还可以存时间和消息 ID。
assistant: 列表是...第一轮机器人回答。下一次请求时会连同用户消息一起发给模型。
user: 那元组呢？第二轮省略了“与列表相比”这层背景，模型需要前两行上下文才能理解“那”。
assistant: 元组...根据之前内容生成的连续回答。├── 和 └── 只是展示层级，不会真的存入消息。

群聊会话 ID 使用：

group:<群号>:user:<QQ号>

私聊会话 ID 使用：

private:<QQ号>
为什么会话 ID 要这样组合
组成部分隔离作用
group / private先区分群聊和私聊，避免同一个 QQ 号在两种场景下误用同一段上下文。
<群号>把不同群分开。同一个人在 A 群和 B 群的聊天不会混在一起。
<QQ号>把同群不同成员分开，避免甲问完后乙说“继续”却接上甲的私有对话。
:只是稳定的字段分隔符，便于生成、阅读和解析唯一键。

群聊键包含群号和用户号，私聊键只需用户号，因为一条私聊事件本身没有群号。

这样可以避免两个常见问题：

  • 同一个群里，甲的经历被错误套到乙身上。
  • 一个群的聊天内容泄漏到另一个群。

随后把内存中的记录写进 JSON：启动时 load，每轮完成后 save。当前项目使用“先写临时文件，再替换原文件”的方式，减少断电时写坏数据的概率。

第 11 步

记住群友，并引用正确的人

群聊里只有纯文本还不够。机器人要知道谁在讲话，也要让大家看清它在回答谁。

身份记录

identity.py 观察每条群消息，保存：

群号 → QQ号 → 昵称、群名片、最后出现时间

调用模型时，把当前用户描述成类似：

QQ 987654321，群名片“小明”，QQ昵称“Ming”
身份记录为什么同时保留三种信息
字段用途
群号 → QQ号用群和账号作为稳定索引；昵称会改，QQ 号通常更适合作为内部身份键。
群名片成员在当前群展示的名字，回答时优先使用它通常更自然。
QQ昵称群名片为空时的备用显示名。
最后出现时间判断记录是否陈旧，也可用于清理长期没出现的缓存。

传给模型的示例是一段身份说明，不是让模型自行猜测账号。生产代码还应避免把这些身份信息发送给无关群或写进公开日志。

引用回复

普通文字回复由三个消息段组成：

[reply:原消息ID] + [at:提问者QQ] + [text:回答]
OneBot 消息为什么要分成三个段
消息段QQ 中的效果
[reply:原消息ID]引用具体原消息，让群友能展开查看机器人正在回答哪句话。这里需要的是消息 ID，不是用户 QQ 号。
[at:提问者QQ]真正 @该用户并产生 QQ 的 at 消息段，比在文字中手打昵称可靠。
[text:回答]承载最终回答正文。
+这里只表示按顺序组合，不是发三条独立消息。最终是一条由多个段组成的 Message。

语音是例外。某些 QQ 客户端或 NapCat 版本无法稳定解析“引用 + 语音”，所以语音回复只发送独立的 record 消息段。

第 12 步

把功能改造成 Tool Call

关键词判断只能处理固定说法。例如只判断“看图”，用户说“总结我回复的截图”就可能匹配失败。Tool Call 的做法是：告诉模型有哪些工具，让模型根据语义选择。

第一部分：声明工具

{
  "type": "function",
  "function": {
    "name": "web_search",
    "description": "搜索互联网，实时信息或用户明确要求联网时调用。",
    "parameters": {
      "type": "object",
      "properties": {
        "query": {"type": "string"}
      },
      "required": ["query"]
    }
  }
}
逐层看懂这个工具声明 JSON
JSON 字段格式模型会怎样使用
{ ... }最外层花括号表示一个 JSON 对象，由键和值组成。一整个对象描述一个可供模型选择的工具。
"type": "function"键和值都是字符串，冒号分隔键和值，逗号分隔相邻字段。告诉 API 这是函数型工具，而不是普通聊天内容。
"function": { ... }function 的值又是一个嵌套对象。内部集中放工具名、说明和参数结构。
"name": "web_search"稳定的机器可读名称，通常使用字母、数字和下划线。模型决定搜索时返回这个名字；执行器必须用完全相同的名字找到对应 Python 方法。
"description": "..."给模型阅读的自然语言说明。这是模型判断“何时该调用”的主要依据，应说清用途和边界，不能只写“搜索”。
"parameters": { ... }使用 JSON Schema 描述参数。约束模型应该生成哪些参数以及参数类型。
"type": "object"表示工具参数整体是一个对象。一次调用的参数形如 {"query": "今天的新闻"}。
"properties": { ... }列出允许出现的每个参数字段。这里只声明一个名为 query 的搜索词。
"query": {"type": "string"}把 query 约束为字符串。执行器拿到的应是搜索文字，而不是数组或数字。
"required": ["query"]方括号是数组，列出不可缺少的字段。模型调用 web_search 时必须给出 query。

工具声明只是一张“菜单”，不会因为写了 web_search 就自动联网。Python 端仍要验证模型给出的 JSON、检查权限，再把工具名分派到真正的搜索函数。完整项目还应加入 "additionalProperties": false 来拒绝未声明字段。

    if 模型没有要求调用工具:
        return 模型的最终回答

最后再要求模型根据已有结果诚实作答
逐行看懂工具循环：模型为什么可能请求很多次

下面是为了讲流程写的伪代码：中文条件和箭头不能直接交给 Python 运行，但每一行都对应完整项目中的实际步骤。

伪代码控制逻辑实际意义
while 还没有超过工具轮数:while 表示条件仍成立就重复；每轮都要增加计数。允许模型“先查消息、再导入文件、再运行代码”，同时用上限防止无限循环和费用失控。
response = 请求 DeepSeek(messages, tools)把当前消息历史和工具菜单一起发给模型。模型可以直接回答，也可以返回一个或多个结构化 tool_call。
if 模型没有要求调用工具:检查响应中是否缺少工具调用。没有工具调用通常表示模型认为信息足够，已经给出了面向用户的最终文字。
return 模型的最终回答return 结束整个工具循环。把回答交还给 QQ 消息处理层，不再请求下一轮模型。
for tool_call in ...:for 逐个处理模型在本轮要求的工具调用。一轮可能同时搜索多个关键词；仍需限制单轮调用数量。
result = await execute_tool(...)解析工具名和参数，异步等待真实执行结果。执行搜索、OCR 或沙盒等动作。这里必须做参数、用户权限、群范围和超时检查。
messages.append(工具执行结果)append 在消息列表末尾追加一条 tool 角色消息。工具是 Python 执行的；必须把结果再交给模型，它才看得到搜索结果或命令输出。
最后再要求模型...达到轮数上限后，关闭工具选择再请求一次最终回答。避免只报“工具次数过多”，要求模型根据已经取得的结果说明完成了什么、还缺什么。

这里要特别分清：

  • ai_tools.py 是工具菜单，只描述名字、用途和参数。
  • execute_tool() 或 AgentToolExecutor 才执行真实动作。
  • 工具结果必须重新交给 DeepSeek，模型才能根据结果组织最终回答。
工具循环必须有限制 要限制总轮数、单轮调用次数、单个结果长度和累计上下文长度。达到上限后要求模型停止调用工具，并明确说明任务卡在哪里。

第 13 步

逐层增加高级功能

基础 Tool Call 跑通后，再按下面顺序增加模块。每次只新增一个工具并单独测试。

web_search.py：联网搜索先请求 DuckDuckGo HTML；没有结果时使用 Bing RSS。返回标题、摘要和完整链接。
ocr.py：图片文字识别寻找当前图片、被回复图片或同一用户五分钟内最近图片。macOS 使用 Vision，其他环境可调用 NapCat OCR。
voice.py：语音NapCat 负责语音转文字；Edge TTS 或 macOS say 生成语音，再编码为 QQ 可用的腾讯 SILK。
stickers.py：表情学习群里的图片和稳定 QQ 表情 ID，随机发送；普通文字回答使用颜文字。
long_term_memory.py：长期记忆保存明确的稳定偏好和项目约定，严格区分群记忆与个人记忆，并拒绝保存疑似密钥。
model_preferences.py：模型切换按当前会话保存模型，不影响同群其他用户。
proactive.py：主动接话与暖场普通消息达到数量后低概率接话；群聊空闲达到阈值后按每日上限暖场。
tasks.py：任务管理登记耗时 AI 任务，让用户通过 /任务 查看、通过 /停止 取消。

高级功能接入主流程时遵循同一个模式：

声明工具
→ 判断本轮是否具备调用条件
→ 把工具交给 DeepSeek
→ 安全执行
→ 返回结构化 JSON
→ 让 DeepSeek 生成最终回答
→ 保存本轮上下文
高级功能接入主流程时，每一步的责任
步骤必须完成的事情
声明工具给出稳定名称、清楚描述和严格参数 Schema，让模型知道工具存在。
判断本轮是否具备调用条件按聊天类型、用户白名单、平台能力和配置开关裁剪工具菜单。例如普通群友不应看到沙盒工具。
把工具交给 DeepSeek只发送声明，不提前执行；由模型根据当前语义选择。
安全执行Python 端重新验证参数、路径、群号、所有者、超时和大小上限，不能盲目信任模型。
返回结构化 JSON让成功、失败、数据和下一步建议都有固定字段，模型更容易准确理解。
让 DeepSeek 生成最终回答把工具结果作为 tool 消息追加后再请求模型，由模型整理成自然语言。
保存本轮上下文只在得到最终结果后记录必要内容，长工具输出应截断，秘密数据不应进入记忆。

第 14 步

加入隔离项目沙盒

为了让机器人真正创建项目、安装依赖和运行测试，项目后来增加了 Docker 沙盒。模型不能直接读取宿主机，而是在临时容器的 /workspace 中工作。

一个完整代码任务可能这样执行：

say("开始创建项目")
→ sandbox_create("python")
→ sandbox_write_file("src/main.py", ...)
→ sandbox_exec("pip install -r requirements.txt")
→ say("依赖安装完成，开始测试")
→ sandbox_exec("pytest")
→ sandbox_exec("tar -czf project.tar.gz ...")
→ send_file_from_sandbox("project.tar.gz")
→ 宿主停止容器并保留 /workspace
一个沙盒项目任务是怎样一步一步完成的

箭头表示先后顺序，不是 Python 运算符。真正执行时，模型每次发出 Tool Call，机器人取得结果后再决定下一步。

调用输入或输出作用
say("开始创建项目")输入一段进度文字。立即在群里发中间状态，避免长任务几十秒没有回应。它不创建文件。
sandbox_create("python")输入沙盒类型，输出沙盒 ID。创建隔离的 Python Docker 容器；后续调用都要携带并验证这个 ID。
sandbox_write_file(...)输入相对路径和文件内容。在容器的 /workspace/src/main.py 写代码；路径验证阻止写出工作区。
sandbox_exec("pip install ...")输入命令，输出退出码、标准输出和错误输出。在容器内安装项目依赖，不会安装到机器人宿主机的 Python 环境。
say("依赖安装完成...")第二条独立进度通知。说明前一个阶段已完成；say 可以按实际进度多次调用。
sandbox_exec("pytest")运行测试并返回结果。模型根据失败输出修改代码，再次运行测试，直到通过或达到工具限制。
sandbox_exec("tar -czf ...")在容器内执行打包命令。把多个项目文件打成一个便于上传的压缩包。
send_file_from_sandbox(...)输入沙盒内文件路径。机器人读取受限工作区中的产物并上传到当前群，不能借此发送宿主机私人文件。
宿主保留工作区不需要模型调用。任务结束后只停止容器；/workspace 保留供复查和补发，真正删除必须由管理员明确执行。

当前沙盒的重要限制：

  • 每个容器最多 1GB 内存、1.5 CPU、128 个进程。
  • 不挂载机器人项目目录或宿主机私人文件。
  • 文件路径必须位于 /workspace，拒绝绝对路径和 ..。
  • 用所有者哈希验证沙盒，不能访问其他用户的容器。
  • 群历史和群文件只允许读取当前群的数据。
  • 文件大小、命令时间和终端输出都有上限。
沙盒默认应该关闭 先设置 AI_SANDBOX_ENABLED=false。准备启用时，务必在 AI_SANDBOX_ALLOWED_USERS 中只填写自己的 QQ 号，并保持 Docker 和系统及时更新。

第 15 步

为关键边界补测试

测试不是为了证明“代码没有任何问题”，而是防止以后修改时把已经能用的能力弄坏。当前项目重点验证：

  • 上下文重启后仍能加载，损坏 JSON 不会让机器人崩溃。
  • 群记忆、个人记忆和不同用户之间互相隔离。
  • 语音回复不会附带引用，文字回复仍会引用并 @用户。
  • Tool Call 达到上限后会停止，并要求模型给出诚实结果。
  • 自然语言请求由模型选择工具，不再依赖固定关键词。
  • 沙盒路径不能逃出 /workspace，取消任务会终止子进程。
  • 群文件和消息工具不能读取其他群的数据。

运行测试：

source .venv/bin/activate
python -m unittest discover -s tests -v
逐段看懂测试命令
命令部分含义
source .venv/bin/activate先使用安装了项目依赖的虚拟环境；它与启动机器人时的激活动作相同。
python -m unittest让当前 Python 以模块方式运行标准库测试框架，确保测试使用同一个虚拟环境。

-s tests-s 是 start directory，要求从项目的 tests 目录开始寻找。

每增加一个高风险能力，都先写至少一个“正常成功”测试和一个“越权或失败”测试。

先学会看方法名和调用链

下面开始逐个解释当前运行代码里的函数和类方法。不要把所有方法背下来，先判断它属于 “接收事件、整理数据、调用模型、执行工具、发送消息”中的哪一步。

get / render / save分别表示读取、转换成文本、保存到磁盘。

方法所属阶段这一层只负责什么
handle_group_activity()后台观察先观察每条群消息，更新用户身份、最近图片和语音、群活跃时间；它通常不直接回答。
handle_mention_ai()事件入口由 NoneBot 在群友 @机器人时调用，提取问题和事件元数据，再把工作交给公共流程。
_finish_tracked_ai()回复调度准备任务执行环境，并在结果回来后选择文字、语音或其他消息形式发送。
_run_tracked_ai()任务管理把耗时请求登记到任务表，使 /任务 能看到它、/停止 能取消它。
_ask_ai()请求准备收集系统提示词、当前用户、短期上下文、长期记忆、模型偏好和本轮允许的工具。
ask_deepseek_with_tools()模型循环反复请求 DeepSeek：模型直接回答就结束，模型请求工具就执行后把结果放回消息列表。
_create_completion()网络请求真正调用兼容 OpenAI 的聊天 API，并处理请求参数和底层响应。
execute_tool()普通工具分派根据受支持的工具名执行搜索、OCR、语音、表情或记忆等本地能力。
AgentToolExecutor.execute()Agent 工具分派执行沙盒、群文件、历史消息和进度通知等需要更多事件上下文与权限判断的能力。

_reply_message()消息渲染把回答字符串转换成 OneBot Message，并按场景加引用与 @；它不负责生成答案。
_finish_safely()真正发送调用 Matcher 或 Bot 的发送能力，并把 NapCat 超时等平台异常转换成可控日志与结果。
handle_group_context_recorder()后台收尾观察群里的普通消息并写入群上下文，让机器人以后能理解大家正在聊的主题。

最关键的分界是：_ask_ai() 到模型与工具这一段负责“得到答案”；_reply_message() 和 _finish_safely() 才负责“把答案变成 QQ 消息并发出去”。

同一条群消息可以被多个 block=False 的后台处理器观察。优先级数字越小，通常越早运行；真正回答用户的处理器使用 block=True，避免重复回答。

“返回字符串”和“发送消息”不是一回事 _ask_ai() 主要负责产生结果；matcher.finish()、 bot.send_group_msg() 才会真正把内容送到 QQ。定位问题时先判断结果是没有生成，还是生成了但发送失败。

  • Git 历史、README、日志和测试文件中没有真实 API Key。
  • 机器人只在指定测试群启用。
  • OneBot WebSocket 没有无鉴权暴露到公网。
  • 长期记忆不会保存密码、Token、验证码和 API Key。
  • 群聊内容、搜索结果、OCR 和语音转写都被当成不可信资料，不能覆盖 System Prompt。
  • 沙盒不挂载宿主机目录，只允许授权 QQ 使用。
  • 工具执行有轮数、时间、文件大小和结果长度限制。
  • 机器人停止时取消运行任务；不再使用的容器及时销毁。
密钥泄漏后的正确处理 不只是删掉聊天或文件，而是立刻到服务商后台撤销旧 Key，创建新 Key，再更新 .env 并重启机器人。

最终结构

每个文件最后负责什么

文件职责
bot.py加载环境、注册 OneBot 适配器、加载插件、启动服务。
ai_chat/onebot_plugin.py显式 OneBot 插件入口：注册消息处理器与启动/关闭钩子。
config.py把环境变量转换成带默认值和范围限制的配置。
deepseek.py构造提示词、调用 DeepSeek、执行 Tool Call 循环。
ai_tools.py定义模型能够看到的工具名称、说明和参数。
paths.py统一确定项目根目录、状态目录和缓存目录。
memory.py短期个人对话和最近群聊上下文。
long_term_memory.py长期个人/群记忆、去重、权限和持久化。
identity.py记录 QQ号、昵称、群名片和最近出现时间。
model_preferences.py按会话持久化模型选择。
web_search.pyDuckDuckGo/Bing 搜索、结果解析和链接输出。
ocr.py寻找图片并通过 macOS Vision 或 NapCat OCR 识字。
voice.py语音转写、TTS、PCM 解码和腾讯 SILK 编码。
stickers.py学习和发送表情包、QQ 自带表情、颜文字。
proactive.py主动插话概率、冷却和空闲群暖场。
tasks.py登记、查看、完成和取消耗时任务。
sandbox.py安全创建和操作 Docker 开发容器。
agent_tools.py连接模型工具、QQ群消息/文件与 Docker 沙盒。
macos_ocr.swift调用 macOS Vision，按阅读顺序输出图片文字。
tools/loadNapCat.js在 macOS QQ 启动流程中加载 NapCat。
tests/验证工具循环、持久化、权限隔离、回复格式、沙盒安全和任务取消。

真正重要的不是一次写出所有功能，而是始终知道消息当前走到了哪一层： QQ 接入、事件分发、上下文组装、模型决策、工具执行、消息发送。 只要一层一层验证，六千行项目也仍然是许多个能单独理解的小步骤。
