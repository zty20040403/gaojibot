# 官方 QQ 接入

当前入口只运行官方 QQ 网关，不需要 OneBot 或 NapCat。接入参数见 [.env.example](../.env.example)，文件和媒体能力见 [宿主配置](qq-official-host-config.md)。

## 身份与绑定

AppID、AppSecret、绑定 pepper 分别放在受保护文件。pepper 是随机生成的 32 字节十六进制字符串。`group_openid` 和 `user_openid` 来自本 AppID 的真实事件，不能用普通 QQ 群号或账号替代。

管理员先通过可信配置核对私聊身份，再绑定管理台账户。群绑定流程为：管理员私聊 `/bind create`，将返回的 `/bind submit …` 在目标群真正 @ Bot 后发送，再回到原私聊确认。管理台登录和群成员身份不会自动授予宿主运维权限。

## 对话与任务

`/help` 显示当前命令。`/clear` 移动当前聊天窗口起点，不删历史；`/memory` 查看会话记忆。`/status` 和 `/kill` 查询或停止后台任务。前台调用 `agent` 后可继续聊天，追加要求通过 `agent_steer` 传给已有任务。

模型空行分段会逐条发送，`say` 用于真实进度。后台只能操作工作区和读取资料，完成后把报告交回前台，由前台发送实际文件。不要向模型提供旧 sandbox_create/项目工具说明。

## 发送与文件

发送结果和回执保存在 PostgreSQL；只在平台确认接受后声称成功。结果不确定时不盲目重发。发送队列按会话排序；所有发送共用每分钟 60 条、每群每分钟 20 条的本地限制，主动消息另按上海日期限制每群每天 1000 条。

文件服务支持普通文件、图片和 SILK 语音，单文件应用上限 100 MiB；小文件走普通上传，大文件走分片上传。平台仍可能因账号能力、文件格式或自身限制拒绝，届时返回实际错误。语音每轮最多一条。群内能下载打开的文件才算完成真实验收。

## 排查

先查看管理台“最近请求”：模型当时看到的提示词、上下文和工具。随后核对 `turn_journal_events`、`background_jobs`、`deliveries` 和 `delivery_attempts`。日志中不打印密钥。部署后的数据处理和回滚见 [上线步骤](deploy-rework.md)。
