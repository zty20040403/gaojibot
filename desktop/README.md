# 高级部署 App

这是独立部署客户端。用户填写自己的服务器、QQ 和模型密钥，服务器上的机器人与开发者的现有高级实例互不关联。关闭客户端不会关闭服务器上的机器人。

Mac / Windows 客户端现在增加“这台电脑”入口，通过本机 Docker Desktop 运行独立的 PostgreSQL、QQ 和 Bot，不需要租服务器、SSH 或手工安装数据库。原有 Linux 服务器部署保留。

## 本机部署

1. 选择“这台电脑”。检测未就绪时，点下载并安装 Docker Desktop，再打开它。macOS 安装确认、Windows WSL2/虚拟化和系统重启需要用户按系统提示完成；App 不绕过这些步骤。
2. Docker 使用 Linux 引擎，至少分配 4 GiB 内存，本机首次安装预留 15 GiB。首次下载运行镜像依赖网络；后续按运行包摘要复用镜像，不会每次打开重建。
3. 点“安装到这台电脑”。数据库、随机密码、数据卷、内部网络和可用端口由 App 自动创建。
4. 在 App 扫 QQ 二维码，填写自己的模型、API Key、管理员 QQ 和启用群，再保存、启用机器人。
5. 控制台直接使用本机回环端口，不建立 SSH。原服务器模式仍只通过 SSH 管理用户选定的服务器。

数据在专属 `gaoji-desktop-<安装编号>-data` Docker 命名卷中。只有管理组件挂载 Docker socket；Bot 不挂载宿主目录、控制器凭据或 Docker socket。管理 Token 存在系统加密凭据存储中，不进入渲染页面。安装记录先持久化，继续原任务不会创建第二套数据库。

Apple Silicon Mac 本机数据库、二维码入口和重启续接已实际验证，详见 [本机验收记录](../packaging/qa/desktop-local-2026-09-15.md)。Windows 未实机验证，真实扫码与群聊仍待用户验收。环境安装要求见 [Docker Desktop Mac 文档](https://docs.docker.com/desktop/setup/install/mac-install/) 和 [Windows 文档](https://docs.docker.com/desktop/setup/install/windows-install/)。

关闭 App 不关闭已启动的容器；睡眠、关机或退出 Docker Desktop 时机器人不可用。电脑与 Docker 恢复后，未手动停止的容器按原策略恢复。“停止机器人”保留数据库与 QQ 登录。不要删除 Docker 数据卷、恢复 Docker 出厂设置或同时在别处登录同一个 QQ。更换 Docker 引擎时 App 会阻止静默创建空数据库。

本机“更新与回退”使用独立 Docker 执行器，不依赖 systemd。回退恢复所选升级前的数据；升级后产生的数据另行保留，不自动合并。原镜像或专属数据卷被手动删除时会拒绝替换，不创建空数据库冒充恢复。

在“功能组件”启用隔离沙盒后，首次应用会安装固定配方镜像。需要 Docker 引擎至少 6 GiB 内存、12 GiB 可用空间；目前工具镜像为 x86_64，Apple Silicon 使用模拟执行，首次编译比原生慢。机器人只接入带认证的沙盒通道，不获得 Docker socket。工具按需安装；专用工作卷和缓存计入“存储管理”。基础聊天不需要打开沙盒。

使用 `0.1.27` 运行包新建的本机实例支持备份迁移；导入仍要求运行包摘要一致，不自动恢复，跨实例恢复后 QQ 要手动确认接管。外部模型/Embedding/Matrix/集群仍需用户自己的接口。访问本机模型时使用 `http://host.docker.internal:端口/v1`，不能把容器内的 `localhost` 当作宿主电脑。服务器“卸载服务、保留数据”的向导没有因此变成本机 Docker 的卸载向导；不要手动删除数据卷。

## Matrix 消息互通

只想使用 QQ 的用户无需开启。这是消息镜像，不是一个另建的 Matrix AI 账户服务：机器人账户需由你创建并加入目标房间；QQ 群也需由机器人加入且在当前实例启用。

1. 在“功能组件”开启“Matrix 消息互通”。填写自己的 Homeserver 地址、机器人用户 ID（例如 `@bot:example.org`）和该账户的 Access Token。
2. 添加会话映射，填写 QQ 群号与 Matrix 房间 ID（以 `!` 开头，不是 `#` 别名或邀请链接）。最多 20 条映射。同一个房间不能绑定不同 QQ 群。
3. 点击“检测 Matrix”。检测仅核对账户、房间成员资格、是否加密和发言权限，不发消息，也不替你加入房间。检测运行在服务器 Bot 网络内，不从桌面直接调用外部接口。
4. 保存设置，再“应用并重新连接”。启用时再次检查，失败不会覆盖正在运行的 Bot 配置。仅保存或勾选开关不代表互通已生效。
5. 在已关联的 QQ 群和 Matrix 房间各发一条普通文字，检查另一端是否收到、发送者是否正确；无关联的群和房间不应出现这条消息。同一 QQ 群绑定多个房间时，这些房间属于同一个共享会话，消息会互相转发，配置前应征得成员同意。
6. 关闭开关或移除映射后保存并应用。尚未发送的旧镜像消息会重新核对当前映射，不再发送到已取消的目标；已发出的消息不会撤回。暂停再重新启用同一映射，不等于清除旧消息历史。

当前只支持未启用端到端加密的房间。不把加密状态查询失败当成“未加密”，也不向已开启加密的房间降级发送明文。附件按现有消息渲染能力降级为说明或链接，不承诺 QQ 与 Matrix 的图片、文件、语音原样互传。请不要为接入而关闭已有敏感房间的加密，另建适合公开互通的房间。

Token 只保存在本实例私有配置中，公开状态仅显示是否已保存，备份按私有密钥处理。更换地址或账户必须重新填写或清除旧 Token；不会把旧密钥发送给新地址。此功能不使用开发者的 Matrix 服务或凭据。检测依据 [Matrix Client-Server API](https://spec.matrix.org/latest/client-server-api/)，不是网页截图或仅检查端口开放。

`0.1.12` 在版本更新前撤下已完成安装器的开机入口，保留它的定义和安装记录；重新启用服务也不恢复这个旧入口。这样后续重启由当前版本的运行服务接管，不会用旧安装包重新校验新版本。源码回归和本地 Linux 验收证据见 QA 记录，不代表 Windows 或 QQ 全流程已验收。

低速环境的离线自检总时间统一为五分钟，仍逐项验证源码、依赖、中文字体和浏览器。更新页分别显示构建和自检阶段；超时不会继续切换版本或重新创建数据库。

1. 在自己的电脑打开 Gaoji，点击“连接第一台服务器”。
2. 填入服务器地址、登录账户，选择密码、私钥文件、系统密钥代理或 Tailscale SSH。使用 Tailscale SSH 时，服务器必须已经允许该网络身份登录；客户端不会绕过登录权限。
3. 第一次连接会显示服务器指纹。核对身份后继续；地址相同但指纹变化时客户端会停止连接。
4. 先看安装清单。只有点击“安装到此服务器”才提交安装；检测阶段不会安装软件。需要 sudo 时，在客户端输入服务器 sudo 密码。
5. 安装期间可以关闭客户端。再次连接会读取同一个安装任务；网络暂断不代表安装失败，也不会直接新建另一套数据库。
6. 安装完成后，手机 QQ 扫码并确认登录。再填写自己的管理员 QQ、模型地址和 API Key。
7. “读取列表”查看服务返回的模型名称；“测试连接”会从服务器真正请求一次简短模型回答，可能消耗该模型服务的额度。
8. 填写希望启用的群号。留空时不回复任何群；勾选“允许所有群”才会放开。私聊和群聊使用的是你登录的机器人 QQ。
9. 保存设置，设置控制台账户和密码，然后点击“启用机器人”。界面只有收到实际 QQ 连接状态才会报告连接成功。
10. 点击“打开控制台”管理机器人。客户端自动建立本地加密转发，不需要另外手写隧道命令。

本地隔离 Ubuntu 的安装和重启已验收到扫码入口；QQ 登录、实际模型回复和文件交付尚未验收。其他发行版及完整维护流程也不能从这一项结果推导为已通过。

## 多个模型怎么配置

“模型目录”中有两个不同的选择框：“默认聊天模型”决定通常由谁回答；“正在编辑的模型”仅切换下方表单，不会改变机器人当前默认模型。

1. 点击加号添加模型，填写方便记忆的名称，例如“日常聊天”“写代码”。选择模型服务，再填写自己的接口地址、模型名称和 Key。
2. 一个模型一份 Key。切换编辑对象时，没保存的内容也会保留；服务器已保存的 Key 不回显。修改地址、服务或协议后须重新输入，不能把原 Key 发送给新服务。
3. 本地千问等无密钥服务，可在高级设置勾选“此服务不需要 API Key”。要移除已存的 Key，点击密钥旁的清除按钮，再保存。
4. 在“模型高级设置”选择服务支持的思考模式、推理强度及工具/识图能力。这里只声明能力，不会让纯文本模型变成视觉模型；不确定的参数保持服务默认。
5. 在“故障时的备选顺序”加入其他已配置模型，用箭头排序。模型 A 不能降级到 B 后再绕回 A；不可选的项目表示会形成这种循环。
6. 识图和章节整理的模型在“功能组件”中选择。删除正在被这些功能引用的模型时，会清掉关联；先确认默认/替代模型是否支持对应功能，再保存并应用。
7. 默认模型不能直接删除：先选择另一个默认模型，再点垃圾桶。删除不会删除聊天记录；历史备份仍可能包含当时的配置和 Key，不等于从所有备份中擦除。
8. 保存后点击“应用并重新连接”让运行中的机器人读取新配置。若有其他管理员更新了服务器配置，App 会拒绝覆盖；保存按钮旁的重新载入按钮可在确认后丢弃本机草稿、读取最新版本。

“测试连接”会使用当前编辑模型的思考/推理设置发一次短请求。测试成功仅表示返回过文字，不证明识图、工具调用或整个降级链都已验收。较高推理强度可能增加耗时与费用，服务不支持的参数会明确报错，不会假装已经生效。

## 备份与恢复

在“模型与启用”页面下方的“备份与恢复”中操作：

- “创建备份”：确认后短暂停止本实例的 Bot 和 QQ 写入，导出 PostgreSQL 并保存配置、QQ 会话及文件。校验完成后恢复原组件状态。
- 列表默认显示最近五份。每份备份右侧有导出和恢复按钮，恢复前会再次确认目标时间；只接受同运行包摘要的备份。同版本号不保证源码摘要相同。
- 恢复先进入独立数据库验证，通过后切换数据。原数据另行保留；Bot 不自动回复，需核对配置和 QQ 后重新启用。
- 中断后优先恢复原状态。已完成数据切换而仅收尾失败时，会继续收尾。页面出现“完成中断恢复”时可提交这个固定恢复操作，不能输入任意命令。
- 备份含聊天记录和密钥，保存在服务器权限为 `0700` 的实例备份目录，归档文件为 `0600`。当前不是磁盘加密格式，不应直接把原始归档公开发送。
- 缓存、日志、浏览器临时锁和可重新下载的公开转写模型不备份。恢复保留已有转写模型，下次启用前重新校验。默认保留现有备份和成功恢复时的原数据；只有在“存储管理”明确清理或启用保留策略后才删除符合条件的旧副本。容量不足时拒绝新建暂存副本，不删除当前数据库腾空间。

### 导出到电脑或迁移到另一台服务器

1. 点击备份旁的下载图标，输入两次至少 12 个字符的独立长密码，在系统文件对话框选择保存位置。文件扩展名为 `.gaojibak`，密码遗忘无法恢复。
2. 在目标服务器详情中点击“导入加密备份”，选择本机文件并输入密码。目标实例必须已安装完成，且运行包摘要与备份一致；第一版不自动迁移不同版本的数据库。
3. 客户端先校验整个文件，再上传。导入只增加一份备份，不覆盖目标数据，也不自动登录 QQ。重复导入同一归档不会增加重复副本；回执丢失时查询持久记录，不盲目重传。
4. 确认原服务器的机器人和 QQ 已停止，再选择导入备份旁的恢复按钮。恢复覆盖目标实例的数据、配置和密钥，但保留目标实例编号与监听端口；原目标数据另行保留。来自其他实例时，恢复后 Bot 和 QQ 均保持停止。
5. 在“QQ 登录”页确认“我已停止原服务器的 QQ”，再点击“启动此处 QQ”。此步骤只启动 QQ 登录入口，不启用机器人；看到二维码后按需重新扫码，已自动登录时核对账号。启动未确认可重试，连接中断不会创建第二个操作。
6. 核对模型设置、QQ 状态和目标群后，再通过 App 启用。不要让同一个 QQ 在两台服务器同时运行。

`0.1.18` 起，新执行的跨实例恢复会持久记录待接管状态。未确认接管时，QQ 不会因重启服务器或重新生成运行配置而启动；普通“启用机器人”也不能跳过它。恢复失败会还原原来的接管状态。这不追溯改变旧版已经完成的恢复；升级前已经在运行的 QQ 不会被无提示地停止。

服务端需包含新传输接口，旧实例应先通过“更新与回退”更新管理器。备份传输期间可取消；取消不会执行恢复。如果断线时服务器已接收完成，列表中可能已有该备份，重试前会核对。传输本身不是可断点续传的恢复任务：退出 App 会中断传输，下次重新选择文件；已完成的导入保留。

第一版单份导出上限为 **32 GiB**。加密使用 Node 内置的 [scrypt](https://nodejs.org/api/crypto.html#cryptoscryptpassword-salt-keylen-options-callback) 和 [AES-256-GCM](https://nodejs.org/api/crypto.html#class-cipheriv)：固定 KDF 参数、随机盐/IV、经过认证的元数据和标签。文件头含版本、容量、时间、摘要及随机实例编号，不含 API Key、QQ 会话或聊天正文。密码只用于电脑端加解密，不写入应用配置、不发送到服务器；文件通过已认证的 SSH 通道传输。

电脑端不创建明文归档，导出先写私有加密临时文件，校验完成后替换目标文件。正常错误和取消会删除本次临时文件，不改已有备份；电脑断电等强制中断可能留下 `.gaoji-export-*.partial`，该文件未完成，不能作为备份。服务器端先写私有暂存目录，校验归档内容和来源后才加入目录；同一文件重试清理自己的未完成暂存，不清理别的备份。

本机串联测试证明了导出、加解密、鉴权、导入和重复回执协议一致；0.1.19 另在两个独立本机 Ubuntu 虚拟机通过真实 PostgreSQL 跨实例恢复、重启与接管到扫码入口的检查。真实 QQ 重登、群消息/文件交付和 Windows 运行仍需后续环境验收；服务器本机备份不能替代异地备份。

## 更新与回退

安装完成的服务器详情中，选择“更新与回退”。这里操作的是该服务器上的实例，不是更新桌面 App 本身；桌面 App 当前仍需下载新的安装包。

1. 先保存“QQ 与模型”里的更改。版本页对比服务器运行包和本 App 携带的运行包；同版本号也可能对应不同的源码摘要，悬停摘要可查看完整值。
2. 点击“更新此实例”，阅读确认内容，需要 sudo 时输入服务器密码。上传内容经过摘要校验；服务端再次核对实例、当前版本和配置版本，避免覆盖其他管理员刚刚保存的设置。
3. 新镜像先通过离线检查，再暂停本实例写入、备份、在数据库副本上迁移和验证。没有核对成功不会直接覆盖原库；只操作本实例，不执行整机 rebuild。
4. 更新中管理器可能暂时停止，但版本页仍通过 SSH 读取独立任务记录。可以关闭 App 后重新登录查看；若显示“待核对”或“已中断”，点击“继续原版本任务”。不要移除连接或重新安装来重试。
5. 切换前失败会恢复原版本和数据。切换后若 QQ 暂未连上，界面会显示未完成并保留新数据；继续原任务只完成核对，不重新迁移或自动丢弃新消息。
6. 需要回退时选择“回退点”再确认。它恢复该次升级前的机器人程序、数据库、QQ 会话和文件，不会合并升级后产生的数据。当前数据另行保留；管理器仍保持新版，避免丢失管理入口。

回退记录默认显示五条，可展开；刷新不会重置选择或关闭确认框。sudo 密码仅用于本次操作，不写入版本任务记录。更新备份和原数据默认保留；“存储管理”可清理符合条件的历史恢复点，清理后不能再从该点回退。磁盘不足时拒绝更新，不删除当前数据腾空间。此流程已经过本地模拟中断测试，但仍需在隔离的真实 Linux 环境验收，不建议先拿唯一一份重要数据尝试回退。

## 存储管理

在已安装实例的详情中选择“存储管理”。需要服务端管理器包含 `0.1.8` 随包的存储接口，旧实例先通过“更新与回退”更新。

1. 点“扫描空间”，查看所在磁盘的可用容量、当前数据分类，以及已核对的完整备份和更新/恢复副本。页面日常每五秒只读取缓存结果，不重复遍历目录；未完整统计的目录会明确标记，不能把显示的项目相加当成服务器全部占用。
2. 默认至少保留 **5 份完整备份、2 个恢复点、7 天**。份数和天数同时保护副本，例如超过七天但属于最新五份的备份仍保留。当天导入的旧备份以导入时间计龄。
3. 修改策略后保存，再点“预览可清理内容”。预览列出具体的实例内相对路径和预计释放空间；确认后只清理这一份计划，不删除预览后新增的副本。计划十五分钟过期，策略、配置或副本发生变化时必须重新预览。
4. 自动清理默认关闭。勾选“每小时自动清理过期副本”并确认保存，才会按该策略定期检查；关闭后不再排新任务，但不会撤销已经提交的清理。要禁用需先等当前清理结束。
5. 清理进度记录在服务器。关闭 App 不取消清理；管理器意外退出后会继续原任务。遇到新挂载或数据变化则停止并保留未处理内容，“继续上次清理”仅接管同一任务，不扩大删除范围。

完成后显示磁盘可用空间的前后值。预计释放值是文件已分配空间的估算，硬链接、文件系统快照和其他进程的读写会造成差异。列表默认五条，可展开；后台刷新不清空正在编辑的策略或关闭预览框。

清理仅覆盖本实例可确认归属的历史副本。仍被恢复点引用的备份、不完整维护记录、符号链接、特殊文件和挂载中的目录不会作为普通副本删除。更新恢复点的记录、旧数据和配套备份按同一组处理；删除前检查整组挂载，避免先删回退入口再发现数据不能删。当前数据库、QQ 会话、用户文件、运行缓存、容器、镜像、共用 Nix/Docker 资源均不在此功能的清理范围。

策略有独立版本号与最近五十次修改记录，清理保留最新任务回执。清理与备份传输、恢复、配置应用及版本更新互相排斥；不能用两个维护入口同时修改实例。此页不是全机垃圾清理器；容量保护和服务卸载是独立功能。

### 运行期容量保护（0.1.15）

在“QQ 与模型 → 功能组件 → 存储容量”设置本实例数据额度和磁盘预留空间，保存设置即可。默认额度 100 GiB、预留 2 GiB；不是立即占用这些空间。修改使用同一个配置版本，过期页面不能覆盖新设置，私有备份/恢复会保留这项配置。旧管理器需更新后才显示字段。

“存储管理 → 实例容量”显示实例目录（数据库、文件、备份、缓存等）、专用沙盒卷和容器写入层的估算，分别检查实例目录与 Docker 所在磁盘。约每分钟后台统计一次，页面刷新只读取结果，不反复遍历磁盘；点“扫描空间”可重新统计。

- 额度或磁盘预留不足时，拒绝新的沙盒创建/写入/代码执行、浏览器写入、图片和视频下载。安装可选模型/沙盒镜像、创建备份、导入备份及准备恢复副本前也检查空间。
- 已有文件读取、发送、备份导出、取消任务和已有清理入口不因额度不足被禁止。只读子 Agent 可以继续，后续实际写文件仍需通过检查。拒绝操作不等于删除或清空任务，未交付文件不会被容量保护自动删除。
- 统计缺失、不完整或超过三分钟未更新时显示“容量待确认”，暂不接收新的大文件操作；恢复后新请求自动通过。已经失败的业务任务仍需按任务状态重试，不承诺自动重做整件事。

这是**写入前的容量保护，不是文件系统硬配额**。不终止正在运行的命令，不能阻止现有进程在两次统计之间继续增长或多个已放行操作同时占用空间。共享镜像、共享构建缓存、容器引擎日志及其他实例的数据不计入本实例额度，但它们占用的实际磁盘空间会影响预留检查。普通聊天仍会少量写入数据库和日志；磁盘已被其他程序完全占满时，不能保证继续正常发送。此项没有授权全机清理，也不改变原有非 App 部署的行为。

## 功能组件

在“模型与启用”中展开“功能组件”。选择后先“保存设置”，再“应用并重新连接”；“已选择”表示保存的配置意图，不代表已通过外部服务健康检测。

| 功能 | 需要填写什么 | 启用后做什么 |
| --- | --- | --- |
| 联网搜索 | 结果数量、超时秒数 | 使用项目现有 DuckDuckGo / Bing 搜索路径；网站限制或网络失败时仍可能不可用 |
| 识图与表情库 | 选择支持识图的模型 | 使用模型看图；不会因此开启看到图片就自动往群里发言 |
| 语音回复 | Edge TTS 音色名称、语速、音调 | 联网合成语音；音色是否可用取决于服务，失败不假装已发送 |
| 网页浏览器 | 开关 | 使用镜像内 Chromium；不默认放开浏览器访问私有网络 |
| 子 Agent | 开关 | 使用已有任务编排；需要执行代码的任务还需启用隔离沙盒 |
| 聊天章节整理 | 整理模型，可跟随默认模型 | 调用模型整理聊天，可能增加模型用量 |
| 语义记忆检索 | Embedding 地址、模型、可选 Key | 用向量检索旧消息；默认 BGE-M3，数据库当前固定 1024 维 |
| 主动参与群聊 | 开关 | 允许既有主动发言逻辑，默认关闭 |
| 群告警 | 自己的 Alertmanager 地址、接收群号 | 接收群必须已启用；默认关闭，不使用开发者的告警服务 |
| 视频深入分析 | 已开启识图、可用视觉模型；可调时长、下载大小、关键帧和转写线程 | 应用配置时下载固定转写模型并实际验证；分析 QQ 上传视频或已有读取器支持的公开视频 |
| 隔离沙盒 | 开关；服务器引擎至少 6 GiB 内存、12 GiB 可用空间 | 安装固定工具镜像，通过隔离通道执行代码与导出产物 |
| 外部集群 | 自己的 Gaoji Cluster Control 网关地址和 API Token；可选查询群、日志群 | 接入已有集群工具、任务与授权流程；网关和上游服务必须由用户提供 |

Embedding 的“测试向量接口”会发一次短测试请求，确认实际返回 1024 维向量。启用语义检索时也会检查一次；这不是评估模型效果，也不表示重新生成了全部历史向量。更换 Embedding 模型可能需要重建旧索引，当前 App 尚未提供跨模型索引迁移。

检测模型、列出模型、检测 Embedding 和集群都通过固定命令在 Bot 的 Compose 网络内执行，检测容器结束后删除。不在宿主机测通就声称容器可用。`127.0.0.1` 在容器里指容器自身，外部服务请填写服务器/容器实际可达的地址。

Key 不写进普通配置，也不通过命令参数传递。留空保持已保存的密钥；更换接口地址后必须重新输入或明确清空，不能沿用原服务的 Key。组件配置与 Key 一起进入同版本私有备份并随恢复版本同步。

旧版服务端没有集群配置入口时，开关显示“服务端需更新”，不会向它发送未知字段。旧版 `0.1.4` 不含新沙盒安装流程。

### 外部集群

1. 在“功能组件”开启“外部集群”，填写自己的 **Gaoji Cluster Control** 网关根地址及其 API Token。不能直接填 SSH 地址、控制台网页地址或原始 MaxOps API；后者是集群网关的上游。优先使用 HTTPS 或可信加密内网。
2. 点“检测集群连接”。检测只读取 `/v1/capabilities`，不会执行命令、创建任务或调整服务器。错误 Token、登录页面、不兼容目录和重定向不会通过；网关认证通过但上游未就绪时单独提示，不表示所有服务器正常。
3. 群号为空时，仅机器人已注册的管理员可以调用集群工具。要让其他群友查询，在“允许集群查询的群号”填写已启用的群；日志可能包含敏感内容，需要再加入“允许查看集群日志的群号”。日志群必须是查询群的子集。
4. 保存设置，再点“启用机器人”或“应用并重新连接”。启用前从 Bot 的网络重新验证网关。更换地址必须重新填写 Token 或明确清空，原密钥不会发送到新地址。
5. 登录后可以先向机器人问“只读检查我能查看的服务器，列出状态和异常”。服务器改动仍按原有管理员及任务授权流程执行；在 App 勾选外部集群不等于豁免操作授权或获得其他服务器权限。

Token 存在本实例的私有、带配置版本的密钥文件中，随私有备份恢复；公开状态只返回“已保存”。Bot 启动时在自己的容器临时文件系统中生成 600 权限凭据文件，关闭后删除。不会新增宿主机 Token 路径或将其暴露在进程参数、Compose 环境和普通状态响应中；关闭功能后不向 Bot 提供这项凭据。

本地测试已覆盖真实 loopback HTTP 认证、兼容目录检查、私有备份、旧配置默认值、启用前失败保护及原有客户端写操作授权。Electron 界面验证了旧服务端兼容、密钥更换、刷新保留输入和窄屏布局。没有连接用户的外部集群，不能据此声称其网关已配置或服务器操作已验收。

### iMessage 消息互通

这是可选项，只使用 QQ 的用户无需开启。需要用户自己准备运行“信息”App 和 BlueBubbles 的 Mac，Linux 服务器中的机器人主动连接这台 Mac；不是把 iMessage 服务安装到 Linux。Mac 需要保持运行、已登录自己的信息账户，并允许 BlueBubbles 读取和自动操作信息 App。前提见 [BlueBubbles 官方说明](https://github.com/BlueBubblesApp/bluebubbles-docs/blob/master/server/README.md)。

1. 在“功能组件”打开“iMessage 消息互通”；旧管理器显示“服务端需更新”时先更新实例。
2. 填写服务器能够访问的 BlueBubbles 地址、BlueBubbles API 密码，以及该 Mac 信息 App 使用的邮箱或手机号。不是 Apple ID 密码，也不是 Mac 解锁密码。优先使用可信 HTTPS 或受保护的内网连接。
3. 添加 QQ 群号与完整 iMessage 会话 GUID。GUID 应由该 BlueBubbles 的配置者提供，形如 `iMessage;+;chat...`；不是联系人昵称、群名或邀请链接。接口来源见 [官方 REST 文档](https://docs.bluebubbles.app/server/developer-guides/rest-api-and-webhooks)。当前 App 尚不提供自动列举全部联系人/会话的入口。
4. 映射的 QQ 群必须在启用群列表中。先征得两边参与者同意：开启后这些指定会话的内容会进入同一 QQ 群的共享时间线。同一个 QQ 群关联的 Matrix 房间和 iMessage 会话也会互转；没有配置的其他会话不读取、不转发。
5. 点“检测 iMessage”。此操作只读取明确指定的会话与消息接口，不读取旧聊天、不发测试消息，不能证明 AppleScript 发送权限或 Apple 账户在线状态正常。
6. 保存并“应用并重新连接”。启用时重新检测，通过后才重配 Bot。请在自己专门的测试会话与测试 QQ 群各发一条短文本，实际核对两个方向是否送达。

首次开启从当前时间开始，正常每轮间隔五秒，仅拉取指定会话。读取窗口和分页进度写入本实例数据库；中断后继续原窗口，已入队消息去重。变更目标 QQ 群、Mac 地址或自身标识会使用新的读取进度，不把旧会话积压转给新的群。Mac 和 Linux 服务器需保持正确系统时间；本功能不是 iCloud 全历史同步器，已经完成时间窗口之后才出现的旧消息不保证自动补入。

文本通过 AppleScript 发送，不要求为此关闭 SIP 或启用 Private API；当前不发送 iMessage 原生引用、图片/文件二进制，媒体沿用既有文字说明降级。发送超时先保留“结果未知”，之后用自己发送的消息回显核对，不盲目重复发送。过久才收到、内容无法匹配的回显仍可能需要人工检查。旧的非 App Private API 配置保持原行为。

密码保存在带配置版本的私有组件密钥文件中，纳入私有备份；修改地址或自身标识必须重填或明确清空。关闭功能不再向 Bot 提供密码。App 不自动开放回调端口、不创建 Apple 账户，也不会配置或修改用户的 Mac。首次关闭后再启用相同映射会从原持久进度继续，不等同于清除聊天。

### 隔离沙盒

先在功能组件中勾选“隔离沙盒”，保存后应用配置。默认每个沙盒 1 CPU / 1 GiB，最多两个；不向 Bot 提供宿主机 Docker socket、任意宿主目录或系统命令入口。

- 首次安装在服务器创建专用构建容器，使用固定 Nix 工具与依赖。编译限制 4 GiB / 2 CPU，可能需要几十分钟；关闭 App 后重新连接会继续查看原任务，不重复安装。
- 镜像配方不变就直接复用，Bot 普通版本升级不会因此重建工具镜像。本机首次构建临时层约 7.03 GiB，最终镜像约 3.00 GiB；安装前空间检查不是磁盘预留，仍应为其他服务留足余量。
- 构建采用专用非 root 账户；打包前和加载后都核对 Nix store 内容。内容异常不启用，也不把校验关掉。旧的只有镜像标签/ID 的记录必须补做校验。
- 成功安装后删除本次构建容器和临时归档；失败时保留本次私有日志与可重试缓存，不全局清理 Docker 或删除用户文件。
- Python、Node、常用 PDF/Office 库和中文字体随工具镜像提供，其他支持的软件包通过既有工具的 `packages` 参数按需安装。
- 文件交接走本实例只读工作卷。Runner 重启后，相同请求编号会复用持久回执；这不表示所有程序都能保存内存，也不证明任意 Bot 任务重启后都会沿用相同编号。
- 本机已实际生成并导出中文 PDF，检查了嵌入字体、可提取文字和渲染结果。QQ 是否收到文件仍需登录自己的 QQ 后验收，不能把沙盒导出成功当作群文件已送达。

### 视频分析

新版运行包部署后，在“功能组件”先启用识图并选择视觉模型，再开启“视频深入分析”，保存并应用。旧服务器没有这项安装能力时会显示“服务端需更新”，不会假装能直接启用。

- 转写工具使用固定摘要的 [whisper.cpp v1.9.4](https://github.com/ggml-org/whisper.cpp/releases/tag/v1.9.4) 源码构建；编译器和源码不会进入最终运行镜像。
- 首次应用从 [固定版本的 Whisper Base 多语言模型](https://huggingface.co/ggerganov/whisper.cpp/tree/5359861c739e955e79d9a303bcbc70fb988958b1) 下载约 141.1 MiB 到本实例 `assets` 目录。精确大小和 SHA-256 写在安装器中，不接受用户传入任意下载地址或宿主机路径。
- 下载失败可以重新应用配置，继续同一份未完成下载；不能通过截断、错误大小或错误摘要的文件。空间不足会停止，不删除聊天或文件腾空间。
- “模型已下载”只是文件状态。真正启用前，还要在 Bot 容器中校验模型并运行一次静音音频加载测试；失败不会继续重配 QQ 或启动新 Bot。
- 发视频并 @机器人说明想看什么。B 站等已有读取器会按自身能力读取；不是所有平台都支持下载原视频，不能把标题或评论当成完整看过视频。视觉分析仍使用用户自己的模型服务，可能产生费用。
- 默认最长 60 分钟、单条 512 MiB、8 帧、2 个转写线程；可根据服务器能力调整。长视频在 CPU 上仍可能超时，时长上限不是完成时间保证。

## 数据与权限

- 实例数据、数据库、QQ 会话和密钥在用户服务器上。PostgreSQL 不对公网发布端口。
- 客户端不会携带开发者的 `.env`、数据库、QQ 登录状态、API Key 或服务器凭据。
- 选择“记住登录信息”时使用系统的凭据保护；不可用时不偷偷改成明文保存。
- API 地址或接口类型改变时必须重新填写密钥，不能将已保存的旧密钥自动发送到另一家服务。
- “移除此连接”只清除本机保存的连接，不删除服务器数据。它不是服务器卸载按钮。
- SSH 安装需要管理员权限，但网页不能随意执行 Shell。配置接口限定为固定操作，且只通过对应 SSH 会话访问。

## 本地开发

在本目录安装锁定的 npm 依赖后执行：

```sh
npm ci
npm run build:runtime
npm run build
npm start
```

`build:runtime` 同时构建机器人原有控制台，并生成白名单源码运行包。打包命令会重新生成运行包，避免把旧安装器带进新客户端。

Python 依赖保持 `uv.lock` 锁定版本和摘要；较大依赖下载使用 180 秒读取超时、最多 3 次 HTTP 重试、4 个并发下载。这些是 [uv 官方提供的下载参数](https://docs.astral.sh/uv/reference/environment/#uv_http_timeout)，不关闭 TLS 或完整性校验。

```sh
npm test
npm run package:mac
# Both platforms use the same prepared runtime payload.
env CSC_IDENTITY_AUTO_DISCOVERY=false npm exec electron-builder -- --win --x64
```

macOS 当前目标为 Apple Silicon，Windows 目标为 x64。macOS ICNS 图标由本机 `iconutil` 生成；Windows ICO 同时生成。`build:icons` 只渲染项目现有标志，不需要联网。

没有配置开发者证书或公证；Windows 包也没有代码签名，首次打开可能受到系统安全提示。不要为了运行预览而全局关闭系统安全保护。

## 服务维护（0.1.9）

1. 进入已安装实例的“服务维护”。选择“卸载服务，保留数据”，需要 sudo 时输入该服务器的密码，再点“生成维护清单”。这一步不会停止服务。
2. 清单列出本实例的服务名、保留数据目录和处理范围。只有点“确认卸载服务”才提交任务；关掉确认框不会提交，密码也不会保存到本机连接记录。
3. 卸载将取消本实例启动项，停止并复查组件，再移除相应服务定义。数据库、QQ 会话、用户文件、备份、停止的容器和工作卷保留；共享 Docker/Nix、镜像与其他服务不处理。这不是彻底释放空间。
4. 进度通过独立的持久任务读取，不依赖已停止的管理服务。连接中断不会自动再发起一次卸载；重新连接后查看原任务。如果执行器确实停止，点“继续原维护任务”，仍使用同一个编号。
5. 已卸载或仍在维护时，QQ/模型和存储页暂停请求；不会把保留的数据当成新服务器重新安装。当前 App 内的配置草稿保留，但关闭 App 会丢失未保存草稿。
6. 要恢复时选择“重新启用原实例”，生成清单并确认。它恢复原先的服务定义和启动项，不替换数据库。卸载前运行的 QQ/Bot 可能重新登录并恢复回复；后台核对组件运行状态和数据库健康后才报告完成。
7. 预览十五分钟过期；配置、版本或服务归属变化时拒绝执行，需要重新预览。旧管理器不具备此入口时，先到“更新与回退”升级，不自动退回安装流程。
8. 卸载完成后才显示“彻底删除实例”。先导出需要保留的备份，再生成删除清单；核对目录、容器和专用工作卷，输入“删除”后确认。此操作会删除本实例数据库、QQ 会话、文件和服务器内备份，不可撤销。
9. 删除发现其他容器引用本实例数据、同名资源缺少归属、数据变化或新挂载时停止，不强制删除。中断后继续原任务，不扩大清单；已删除实例不能用旧安装任务或“重新启用”复活。
10. 删除完成后撤销旧管理凭据及本任务启动项，保留维护审计和共享运行包、镜像、Docker/Nix。显示的数据目录占用不含 Docker 卷/镜像，不能当作全部可释放空间；这不是全机卸载或物理安全擦除。

桌面操作只接受固定维护动作和已登记的实例/任务编号，不接受任意服务名或 Shell。此流程已通过本地模拟服务测试和真实 Electron 界面测试，尚不能据此认定干净 Linux 的卸载、重启及恢复验收已经通过。

## 打包实现

SSH2 的 `cpu-features` 和 `sshcrypto.node` 是可选加速组件。分发包显式排除它们，使用 SSH2 的 Node/OpenSSL 实现，不跨编译或携带另一平台的 `.node` 文件。`npmRebuild=false` 只配合这份没有必需原生 Node 模块的运行时依赖清单使用；将来增加原生依赖时必须重新评估。

包内完整性检查：

```sh
node scripts/verify-package.cjs release/mac-arm64/Gaoji.app
node scripts/verify-package.cjs release/win-unpacked
node scripts/release-manifest.cjs
```

检查包括运行包摘要、必需文件、测试/秘密文件排除和 Windows x64 PE 标识。`release-manifest.cjs` 在两端产物均生成后输出 `release/SHA256SUMS` 和 `release/release.json`，用于核对文件。它不等同于 Windows 实机运行测试。

`tests/verify-ui.cjs` 可用 `GAOJI_PACKAGED_EXECUTABLE` 指向已打包的 macOS 可执行文件，实际验证 IPC、密码遮罩和本机模拟 SSH 加密通信。`tests/verify-setup-ui.cjs` 用进程内测试响应验证配置页面；`tests/verify-updates-ui.cjs` 检查版本页、回执丢失和稳定选择；`tests/verify-backups-ui.cjs` 检查加密备份界面与隐式恢复防护，后二者也支持已打包程序。这些检查不访问任何真实服务器，需要已有的 Playwright 测试运行环境，可用 `PLAYWRIGHT_MODULE` 指定模块路径。

`tests/verify-lifecycle-ui.cjs` 使用真实主进程 IPC、连接记录和维护传输代码，仅将 SSH 响应替换为本机内存数据，覆盖预览不执行、取消清空密码、丢回执、同编号接管、暂停请求、重新启用、独立删除确认和旧安装拒绝。`tests/verify-storage-ui.cjs` 检查保留策略草稿、确认清单与持久清理进度。两者也支持指定已打包程序；`0.1.8` 及以前不含服务维护。

`tests/test_desktop_linux.py` 是额外的本地容器验收，不自动参与普通单元测试。显式设置 `GAOJI_TEST_DOCKER_SOCKET` 为本机 Unix socket、`GAOJI_TEST_DOCKER` 为 Docker 可执行文件、`GAOJI_TEST_RUNTIME_IMAGE` 为 `gaoji-app-local-qa:测试标签`，再运行该测试。它不接受远程 Docker 地址；创建独立数据库并核对迁移、重复管理员初始化和数据库重启，结束后只删除自己创建的临时容器/网络/卷。可通过 `GAOJI_TEST_VIDEO_MODEL` 提供已下载的公开 Whisper Base 模型，验证 Linux 容器内实际加载。此项不替代干净系统安装器、Windows 或真实 QQ 验收。

`tests/test_desktop_sandbox_linux.py` 使用相同的本机 Docker 环境变量，要求已缓存测试中固定摘要的 Python Linux amd64 基础镜像。它创建随机实例检查工作卷隔离、只读交接与超时回收，结束只删除自己的容器和卷；不代表 Nix 软件包安装或群文件发送已验收。
